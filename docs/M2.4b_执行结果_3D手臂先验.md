## 2. 做了什么

### 2.1 多视 3D 方向三角化

`src/vtv/arm3d.py`：

1. **相机**：`load_blender_camera` 从合成场景 `meta.json` 读 Blender 相机
   （location、quaternion、lens、sensor、resolution），转成 OpenCV 约定：
   `R_cv2scene = R_bcw · diag(1,−1,−1)`，`fx = lens/sensor_width · max(W,H)`。
   三机位的外参是真实的（不是 GVHMR 估计的），所以相对相机几何是可信的。
2. **三角化**：对每个 arm segment（shoulder→elbow、elbow→wrist），
   在每个视角由 ViTPose 2D 方向反投影出一个过相机中心的平面；
   3 个平面的公共零空间就是 3D 方向。按关键点置信度加权 SVD；
   `cond = s_min/s_max` 作为视角几何条件数。
3. **坐标**：场景是右手 Blender 世界，PMX/VMD 世界是 `(x,z,y)`（反射）。
   方向先三角化，再映射到 PMX；GT VMD 的 arm 方向与 Blender 场景方向
   在 `(x,z,y)` 下误差 **0.02°**（已验证），所以目标与评测在同一世界。
4. **符号/半球**：平面交点只给出一条**线**（±180° 不确定）。
   当前实现用逐帧预测方向做半球锚定（取离当前手臂更近的一端），
   再按 `smooth` 做 box 平滑。这个选择在“线接近与预测垂直”时会翻转，
   是本轮 jerk 的来源；`--median`/`--max-step` 可加鲁棒滤波，但没有消除翻转
   （见 §5.3）。
5. **应用**：`apply_direction_prior` 只改上臂/前臂的 local rotation：
   由 `Wp = W · inv(L)` 还原真实父世界（含肩C/继承），
   把世界空间 swing `dq` 共轭回 local。手腕 local **不动**，手跟随前臂；
   骨长、非手臂轨、IK 记录不变。
6. **胶囊 guard**：逐帧用 PMX rigid body 胶囊评估 arm-torso / arm-arm；
   若某一对穿透比当前姿态深超过 `pen_tol`（默认 0.01），**拒绝该帧**。
   这是 M2.4 约束门的延续：不允许“姿态指标变好但新增穿模”。
7. **torso-relative 审计**：`body_relative_errors` 把 GT/预测的 arm 方向
   分别旋进各自 chest 坐标系再比较。它对整体旋转不变（有单测），
   所以能区分“手臂真的动了”与“整个人被转了”。
8. **自检**：非手臂轨 1e-9、手 local 1e-9、骨长 1e-6、IK 记录、23 轨、
   目标达成（考虑 cap/guard 跳过）、cap、逐对穿透不增、时序最大步长。

### 2.2 与 M2.3 / M2.4 的区别

| 方法 | 根 | 相机 | 2D 证据 | 结果 |
|---|---|---|---|---|
| M2.3 共享 body_pose | 每视角**固定** GVHMR 根 | 各自 K | 三视 2D 位置 | 最好 −3.6°，front 反而 +0.64°；根误差互相矛盾 |
| M2.4 目标约束/铰链 | 不变 | 不用 | 无 2D | 只修穿透/roll；10° 不可达 |
| **M2.4b 方向三角化** | 不变 | **真实外参** | 三视 2D **方向** | world 可降 12–16°，但 body-relative/穿透/jerk 不过 |

M2.4b 没有做完整的 body-model BA（SMPL-X + 每视角根 + 2D 重投影）；
它做的是 **direction-level 的多视上限**：用真实相机把 2D 方向三角化成 3D 方向。
完整 BA 的 torso 2D 证据在这套 anime 模型上有系统性偏差（pilot 诊断：肩线三角化 vs GT 仍有 **30°**；
不是交付脚本），所以本轮没有把它当成交付，只作为下一步。

## 3. 信息上限：三角化目标本身有多准

GT 只读；target 是同一段 R2 的三视共识，三机位报告相同：

| segment | mean | median | p90 |
|---|---:|---:|---:|
| upper_l | **15.62°** | 12.42° | 30.63° |
| fore_l | **18.42°** | 12.57° | 43.73° |
| upper_r | **24.69°** | 20.54° | 45.69° |
| fore_r | **15.15°** | 11.10° | 33.30° |

对比 M2.4 的 2D 方向残差 3–11°：三角化把“单视 2D 方向”变成 3D 方向后，
误差反而到 15–25°，p90 到 30–46°。原因不是相机，而是：

- 2D 方向本身有 3–11° 的噪声，三视的噪声/关键点偏差并不独立；
- anime 角色的 shoulder/elbow 关键点与 PMX 骨点有系统性偏移；
- 平面交点在小奇异值附近对噪声非常敏感（`cond` 中位 0.08，但第二小奇异值也小）。

**即使应用是完美的，目标也带 15–25° 误差；不可能把 body-relative 误差稳定压到 10° 以下。**

## 5. 为什么 10° 没有达成

### 5.1 世界角包含根/胸，3/4 的 63° 里有一大半不是手臂

| view | chest world error | 说明 |
|---|---:|---|
| front | 11.16° | 小；world 与 body 接近 |
| 3/4 | **51.38°** | 世界角 63.3° 里约 51° 是躯干/根朝向；arm body 只有 33.5° |
| side | 96.16° | 侧面 yaw 不可观测；不作跨机位门禁 |

多视方向先验把手臂转到**世界**目标，等于用肩膀去补根的 yaw；
在真实角色上会表现为“手在世界里对了、肩膀关系错了”。M2.4b 因此把
`body_relative_errors` 作为硬门禁，而不是只看 world。

### 5.2 2D 方向证据到 3D 的衰减

- 单视 2D 方向残差 3–11°（M2.4 §6.1）；
- 三视三角化的 3D 目标残差 15–25°（§3）；
- 三角化后的目标在 front 右臂上甚至比当前预测略差（24.7 vs 25.4，基本平）；
- 目标 p90 30–46°，因此逐帧不可能“再降 10°”。

这不是“优化器没调好”，而是**2D 方向的信息量**问题；M2.3 的结论在
direction level 依然成立，只是失败方式从“根互相矛盾”变成了“目标本身不够准”。

### 5.3 符号/半球的逐帧不稳定

平面交点只给线，不给方向。当前实现用当前预测做半球锚定；
当目标线与预测接近垂直时，选择会翻转：

| variant | 输入最大步长 | 输出最大步长 | 输出 p99 | 门禁 |
|---|---:|---:|---:|---|
| front guard | 31.76° | **86.92°** | 44.81° | fail |
| front upper | 31.76° | 86.92° | 30.03° | fail |
| 3/4 guard | 26.29° | 76.26° | 43.16° | fail |
| 3/4 upper | 26.29° | **140.39°** | 59.02° | fail |
| side upper | 23.16° | **146.87°** | 121.80° | fail |

尝试过的修复：

- `--smooth 7/11/15`（box）→ jerk 仍 7.9–8.2；
- `--median 5` + `--max-step 12`（鲁棒中值 + 每帧 12° 信任域）→ 目标平滑了，
  但 apply 的逐帧半球锚定仍会在垂直处翻转，输出仍有 63–123° 的跳变；
- global sign（整段取一个半球）→ 在部分 segment 上整段反了，front world 反而 +1.2°；
- 逐帧 temporal anchor → 目标符号被锁定在错误的一侧，3/4 也变差。

结论：**没有 torso-relative 3D 先验，仅靠 2D 三角化无法同时解决
“线→方向”的符号和逐帧抖动**；这不是再调一个平滑参数的问题。

### 5.4 手腕/手没有 2D 证据

ViTPose 只有 wrist，没有 palm/finger 方向；手部 local 保持预测值不变。
GT 的 hand body-relative 误差本身就有 36–78°；任何只改上臂/前臂的 prior
都动不了这个自由度。M2.4 已记录：wrist 是一个不可观测自由度。

### 5.5 为什么 guard 版也过不了

guard 在逐帧“候选会让任一胶囊对更深 → 拒绝”的规则下，会让同一段动作
在某些帧改、某些帧不改；这种 on/off 本身就是 jerk 源（8.5–13.2）。
把 guard 变软（允许 +pen_tol、或做 line search）会增加计算量，但
**不会改变目标本身的 15–25° 误差和符号问题**，所以本轮没有继续调。
