### 3.4 pytorch3d shim

创建：

```
shim/pytorch3d/__init__.py
shim/pytorch3d/transforms.py
shim/pytorch3d/ops/__init__.py
shim/pytorch3d/ops/knn.py
```

`transforms.py` 至少实现 GVHMR 用到的：

`axis_angle_to_matrix`, `matrix_to_axis_angle`, `matrix_to_quaternion`, `quaternion_to_matrix`, `matrix_to_rotation_6d`, `rotation_6d_to_matrix`, `so3_exp_map`, `so3_log_map`, `euler_angles_to_matrix`, `quaternion_to_axis_angle`。

要求：

- 用 PyTorch3D 的 BSD 实现或等价实现；**不要猜四元数约定**；
- 写单测：随机旋转 → 各种表示互转 → 误差 < 1e-5；
- `ops/knn.py` 只需一个 `knn_points` 桩（`get_nearby_points` 无调用者）；调用时抛 `NotImplementedError`；
- 运行时 `export PYTHONPATH="$PWD/shim:$PYTHONPATH"`，确保 `import pytorch3d` 命中 shim。

### 3.5 独立 run_gvhmr.py（不要跑 demo.py）

`tools/demo/demo.py` 第 30 行 import `hmr4d.utils.vis.renderer`，该模块 import `pytorch3d.renderer/structures`，并且 demo 最后无条件 `render_incam()`/`render_global()`。只 shim transforms 跑不起来。

做法：

1. 复制 `third_party/GVHMR/tools/demo/demo.py` → `scripts/run_gvhmr.py`；
2. 删除 `from hmr4d.utils.vis.renderer import ...`；
3. 删除 `render_incam` / `render_global` 函数及调用；
4. 保留预处理/推理：`Tracker`、`VitPoseExtractor`、`Extractor`、`DemoPL`；`static_cam=True`；
5. 写 `save_results(cfg)`：保存 `smpl_params_global`、`smpl_params_incam`、`K_fullimg`、`bbx_xys`、视频 fps/尺寸到 `.npz` 或 `.pt`；
6. 先跑 T5，再跑 T1；检查根轨迹/关节方向/尺度。

命令示例：

```bash
export PYTHONPATH="$PWD/shim:$PYTHONPATH"
python scripts/run_gvhmr.py --video testdata/T5_高速舞蹈_001/001.mp4 --static_cam --output outputs/gvhmr/T5
```

## 4. Day 2-3：模型、VMD、兼容性审计

### 4.1 VMD 读写

- 直接 vendor `third_party/mmd2gltf-gui/mmd2gltf/{pmx.py,vmd.py,animation.py,mathutil.py}` 到 `src/vtv/mmd/`，保留 MIT 声明；
- 先读后写：`parse_vmd` → 写回 → 再解析 → 逐帧/逐骨对比；
- VMD 写出注意：四元数 xyzw、0 起帧、30fps、贝塞尔 `(20,20),(107,107)`、IK 段 20 字节骨名、表情名 15 字节。

### 4.2 三模型 profile

- 解析 PMX：骨名/父级/rest/flags/inherit/fixed_axis/local_x,z/IK/layer；
- 解析 Blender armature（如果实际播放用 .blend）：骨名/父级/rest matrix/bone roll/constraints/IK/custom props；
- 对比：骨名/骨数/层级/rest/roll/约束差异；
- 已知差异：提弗洛斯 Blender 侧 1202 根 vs PMX 解析 1182 根；三模型都用全角 `左足ＩＫ`；有肩 P/C、腿 D 链、twist 主骨 fixed_axis；
- 输出 `profiles/<model>.json` 与 `profiles/<model>_blender.json`（如用 Blender）。

### 4.3 兼容性审计（M0 门禁）

按顺序做：

1. **R1/R2 已知-good**：在三个模型上播放，视觉 + 世界关节；确认环境；
2. **identity VMD（全零）**：应保持 bind pose；
3. **单骨旋转**：上臂/肘/腕/大腿/膝/踝/肩，各 ±30°；看方向/轴/父子；
4. **IK on/off**：腿是否被 IK 拖住；
5. **D 链/P-C**：动 FK 腿/肩，看 mesh 是否跟随；
6. **twist**：前臂/小腿，检查 candy-wrapper；
7. **根/缩放/贴地**：位移/身高；
8. **VMD 格式 round-trip**：与 mmd2gltf 求值对比；
9. **PMX vs Blender armature**：骨名/骨数/rest/roll/约束；
10. **现有 VTV 输出**：reze/GVHMR/QuickMagic 的一份 VMD 套模型，和 R1/R2 对照，定位错配项。

判断：

- R1/R2 正常、VTV 错 → 查 VTV 重定向/映射/VMD 写出；
- R1/R2 也错 → 查播放环境（Blender armature/MMD Tools/导入/约束/bone roll）；
- 同一 VTV 在 MMD 正常、Blender 错 → 查 Blender armature/导入设置。

输出：

- `compatibility_report.json`：匹配/缺失/层级/rest/IK/P-C/D/twist/scale/morph/armature 差异；
- `safe_mode` adapter：只写匹配标准骨、强制 IK off、物理冻结、rest 补偿、缩放贴地、未知骨不写。

1. **不要直接跑 `demo.py`**：需要 pytorch3d renderer；用 `run_gvhmr.py`。

7. **不要把 VMD 直接套到不同模型就当作“重定向”**：VMD 是相对各自 bind 的局部旋转，不是跨模型格式。
8. **不要只做骨名映射**：rest pose、P/C、D 链、twist、IK、bone roll、Blender armature 都要查。
9. **不要全局大滤波**：只修 flagged 帧，保留舞蹈发力。
10. **不要提交权重/PMX/VMD/测试视频**：开源仓库只放代码/脚本/配置。
