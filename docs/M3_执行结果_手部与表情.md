### 2.2 手部：从 MediaPipe 到 PMX 手指

**只信任旋转不变量**：

- 每指三个关节的屈曲幅度 = 相邻指节方向的夹角（无符号）；
- MCP 并拢/张开 = 近节指向在手掌平面内相对手掌轴的角度（朝 index 为正）；
- 拇指 = 对掌（在掌平面内朝手指方向）+ MCP/IP 屈曲。

**掌面/屈曲方向由目标模型静止几何决定**，不由 MediaPipe 的深度符号决定：

```
u      = normalize(middle MCP - wrist)          # 沿手掌
l      = normalize(index MCP - pinky MCP) ⟂ u  # 朝拇指侧
n_palm = ±(l × u)                               # 符号由拇指根位置决定（拇指根在掌侧）
```

- 屈曲轴 `a = d_rest × n_palm`，正角度把指节转向掌心；左右手都成立；
- 并拢轴 `a_spread = d_rest × l`，正角度朝 index 侧；避免 MMD 左手系下 `n × d` 的符号翻转；
- 每根骨骼的局部四元数用 **最小 swing** 从静止方向转到目标方向，不引入 twist。

**关键修正**：手指局部旋转是**手部相对**的，不能抵消手腕旋转。首版错误地把 wrist world quat
代进父级链，导致手腕转动时手指局部四元数补偿出 180°（手不跟腕、VMD 里出现 180°/帧）；
修正后 `angles_to_local_quats()` 与手腕无关，手指随手腕 FK 自然转动，角步长从 180° 降到
p95 1.97°。

**级别与门控**（每侧独立）：

- 段 = 连续有检测的帧；段内计算 valid 比例、掌长 CV、3D/2D 屈曲角一致性、角度步长 p90；
- L0：段 ≥3 帧、valid ≥0.7、步长 ≤30°、掌长 CV ≤0.22、逐帧 3D/2D 一致 ≤28°、score ≥0.5、3D 有效；
- L1：段 ≥3 帧、valid ≥0.6、步长 ≤50°、掌长 CV ≤0.22、逐帧一致 ≤35°；2D 角度 × 拟合增益
  （本次 1.5，上限 1.5）× 0.85 阻尼；
- 段内可信帧 <2 → 整段 fallback；L2 = 手腕可见（ViTPose 置信 ≥0.35），L3 = 更差；
- 平滑：3 帧中值（仅测量段）+ EMA（0.38/0.22）+ 逐关节速率限幅
  （MCP 22°/帧、PIP 24°、DIP 16°、spread 10°）+ 关节限位（MCP 0–85、PIP 0–105、DIP 0–70；
  屈曲不小于 0，杜绝反关节）。

**左右手消歧**：裁剪侧别来自身体 COCO 腕（9/10）；若检测腕明显更接近对侧身体腕
（`d_other < d_self − 0.5×palm`）则拒绝。本轮左右各拒绝 1 帧。

### 2.3 表情：blendshape/几何 → 每模型 morph

- 语义通道（12）：`blink / wink_l / wink_r / smile / surprise / angry / sad /
  mouth_a / mouth_i / mouth_u / mouth_e / mouth_o`。
- 每模型别名从 `profiles/*.json` 的 `morphs` 生成（只选实际存在的名字）：
  `まばたき`、`ウィンク`/`ウィンク右`、`笑い`、`びっくり`、`怒り`/`怒り目`、`困る`/`悲しい目`、
  `あ`/`い`/`う`/`え`/`お`；三模型全部解析成功（无缺失）。
- L0：blendshape→语义；L1：EAR/MAR 几何（**默认不驱动口型**，动漫嘴部 landmark 不可信；
  单侧闭合→软双侧眨眼，不产生可见 wink）；L2/L3：中性 + 程序化眨眼。
- 平滑：3 帧中值（眨眼不做中值，避免 3 帧眨眼被抹掉）+ EMA（普通 0.34、眨眼 0.55）+
  速率限幅（普通 0.22/帧、眨眼 0.55/帧）；每帧最多 4 个 morph、总权重 ≤1.15。
- 眨眼可靠性：若 `blink>0.6` 连续 >12 帧，判为不可靠并替换为程序化；口型长保持同理降权。
- 程序化眨眼：固定 seed，间隔 2.2–4.6 s，4 帧形状 `[0.15, 0.62, 1.0, 0.55, 0.12]`，
  避开检测到的眨眼 ±3 帧。
- 头/脸检测：头部 5 尺度裁剪 512；`bbox_ok`（比例/填充）+ 眼/颊 patch 对比（眼区更暗或高对比）
  才算可用；段级用眼点帧间位移 p90 门控（L0 ≤9 px，L1 ≤22 px）。

### 2.4 装配与证书

`assemble_handface_vmd.py`：

1. 身体轨原样复制（不重采样、不改曲线）；
2. 每帧每指计算局部四元数；四元数半球连续（`q·q_prev < 0` 则取反）；
3. 手指轨 30 条、位移 0；
4. morph 只写 profile 存在的名字，稀疏关键帧（离开 0 时补 0）；
5. IK off 从身体 VMD 原样复制；
6. 写出后重新解析并校验：身体逐帧/逐通道一致、53 轨、IK 4 off、无 D/helper、
   quat 单位、回读 replay（组合 FK 对比目标方向）≤1e-5°。

## 3. 关键设计决策

### 3.1 为什么不用逐帧 MediaPipe，而用“段级 L0/L1 + fallback”

M3.0 已量化：校验后的检测只有 4–7%，最长 3–4 帧，角度 p95 26–63°/帧。逐帧写入会直接抽搐。
段级门控把“偶发认出”变成“短段自然手势”，其余交 fallback；这符合指导“L2/L3 自然 fallback 是正确结果”。

### 3.2 为什么 L1 默认不驱动口型

T5 的动漫嘴部 landmark 在多数帧落在脸上错误的深度/位置（MAR 0.25–0.7，明显不可信）。
若按 MAR 驱动 `あ`，会得到一张持续半张的嘴——正是验收禁止的“半张脸持续扭曲”。
因此 L1 只用 EAR 驱动眨眼，口型交 L0 blendshape（T5 无 L0）或中性。

### 3.3 为什么三模型要分三次装配/渲染

VMD 不是跨模型可移植格式。luoxi/tiflos 的身体轨必须先用 M1 adapter 从 si 身体 VMD 重定向
（`outputs/m3/t5_body_{luoxi,tiflos}.vmd`），再按各自 profile 的 finger_map/rest 装配手指。
直接把 si 的 VMD 套到另两个模型会产生不同手臂姿态（rest/A-pose 差异），不是 M3 的职责。

### 3.4 Blender morph 导入的两个坑

1. MMD Tools 对“只选 armature”的导入只导骨骼，不导 morph；必须同时选中带 shape key 的 mesh。
2. .blend 里已有 idle face action（`祀_face` 等），不清掉会叠加在 VMD morph 上；
   导入前把 shape key 的 action 清空，VMD 才独占表情。

两者都已在 `scripts/mmd_blender.py` 的 `import_vmd()` 里处理；导入后逐模型验证
`まばたき` 在 Blender 帧 112–116（VMD 111–115）为 `0.15/0.62/1.0/0.55/0.12`。

## 8. 已知上限

1. **手部 L0/L1 覆盖率低**（左 8.3%、右 1.7%）：T5 手掌 23–50 px、大袖子/头发遮挡、动漫手套；
   MediaPipe 的可靠检出只有几帧一段。可见段自然，但**大部分帧是 fallback 微屈**，
   不是“跟随视频的高保真手指动作”。这是 M3.0 已量化的输入上限。
2. **L1 仍是 2D 推断**：增益 1.5 + 0.85 阻尼；短段内可能出现“手势大致对、细节不对”。
   已用段级门控把 2 帧段/不一致段降为 fallback。
3. **表情只有眨眼**：T5 没有 L0 blendshape；L1 口型默认关闭（动漫嘴部 landmark 不可信）。
   因此没有口型/微笑/情绪 morph；三模型的中性脸 + 自然眨眼是正确 fallback。
4. **没有 L0 表情**：MediaPipe 在动漫脸上的网格偏移导致 L0 条件（≥4 帧、眼点步长 ≤9 px、
   patch 通过 ≥60%）没有满足的段。
5. **L1 眨眼可能误判**：EAR 来自可能偏移的动漫脸网格；已用全局基线、软双侧眨眼
   （单侧→不显示 wink）、0.38 上限与平滑，视觉上是轻微半闭而不是抽动；但仍不是
   “逐帧真实眼睑状态”。
6. **提弗洛斯手指不可视**：手甲包住手；只能验证不畸变/不穿模。
7. **MANO 专家缺失**：WiLoR/HaMeR 未运行（无 MANO）；替换点见 M3.0 §4。
8. **左右手消歧是阈值规则**：极近交叉手仍可能被身体腕误分；本轮各拒绝 1 帧，未见视觉问题。
