## 2. M5 目标

### 2.1 长视频/分段 CLI

- 支持任意长度视频（至少 60–120 秒）不爆内存、不中断；
- 分段处理，段间重叠/上下文，VMD 合并后帧数正确、无重复/缺帧；
- 根轨迹、接触、脚滑、流式缺口在段边界连续；
- 每段可缓存/断点续跑；失败只重跑该段；
- 一条命令：`run_vtv.py --video ... --chunk-seconds 10 --overlap 1.0 ...`；
- 默认反馈档不变；长视频默认仍是保守档。

### 2.2 取景修复

- 提弗洛斯宽姿态（手臂展开）不被 2K 画面裁掉；
- 每模型 auto-frame：按全片/分段 bbox + margin 计算相机，before/after 用同一相机；
- 不改变动作/ root/VMD；只改相机；
- 三模型 2K 静帧/短片检查：手/脚/头不越界。

### 2.3 发布候选

- 安装：`requirements.txt`/可选 `pyproject.toml`、`check_env.py`；
- 文档：安装、一条命令、长视频、配置、缓存、QC、known issues；
- demo：不提交受限素材；准备可替换的 demo 清单；
- 许可：LICENSE/NOTICE/THIRD_PARTY_NOTICES/MODEL_LICENSES 与代码/权重边界；
- CI/自检：单元测试 + `check_env` + 小样本 smoke；
- **不实际公开仓库/不 commit**，除非用户明确授权；只准备 release candidate。

## 3. 长视频设计

### 3.1 分段策略

- 默认段长 10 秒（300 帧），重叠 1.0 秒（30 帧）；
- 每段独立跑完整管线；重叠区用于边界平滑/接触/根轨迹对齐；
- 合并时：
  - 非重叠区保留前段；
  - 重叠区用权重/速度匹配过渡，不硬切；
  - 帧号连续，最终帧数 = 输入帧数；
  - root XZ/Y、脚接触、脚滑、jerk 在边界检查；
- 不把段边界放在动作关键帧上；默认均匀切，允许 `--chunk-frames`。

### 3.2 VMD 合并

- 每段输出 53 轨 + morph + IK off；
- 合并后仍 53 轨、30 手指、4 IK off、无 D/helper、手指位移 0；
- morph 关键帧合并后不重叠/不跳变；
- 对每段做证书，合并后再做一次全局证书；
- 用 `pipeline.py` 的 manifest 记录段输入/输出/hash。

### 3.3 内存/时间

- 8GB 显存：GVHMR 按段跑，段间释放；
- CPU 阶段可串行；缓存中间产物；
- 不要求 RTF；报告总耗时/每段耗时；
- 60 秒视频分 6–7 段，允许小时级。

### 3.4 验收

- 60–120 秒视频（可用 T5/T1/T2 循环或拼接）跑通；
- 帧数正确、无重复/缺帧；
- 段边界无冻结/跳变/脚滑突变；
- 三模型至少一个长视频、2K 抽帧；三模型短片段 2K 保持；
- 缓存/断点：中断后只重跑未完成段；
- QC 报告段级/全局。

## 5. 发布候选

### 5.1 代码/包

- `run_vtv.py` 作为唯一入口；`configs/pipeline.json` 默认；
- `requirements.txt` 固定 numpy<2/torch 2.3/opencv 4.11/mediapipe 1.1.1；
- 可选 `pyproject.toml`/`vtv` console script；
- `check_env.py` 覆盖模型/权重/Blender/ffmpeg；
- 不把 `outputs/`、`models/`、`third_party/`、PMX/VMD/视频/venv 入库。

### 5.2 文档

- 安装（Windows/8GB/路径）；
- 一条命令 + 长视频命令；
- 配置（feedback default/off/full、chunk、render）；
- 缓存/断点/重跑；
- QC 读法（task_gate vs secondary；回退原因）；
- known issues（手部覆盖低、T5 jerk 余量、提弗洛斯取景、真实视频未验证）；
- 许可/引用/权重下载说明。

### 5.3 发布前检查

- 仓库仍 private；**不 commit/不公开**，除非用户明确说。
