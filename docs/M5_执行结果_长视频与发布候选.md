## 3. 长视频：分段、对齐、合并

### 3.1 切段

80.67 s 源 → 30 fps 主视频 2420 帧（源已是 30 fps，`video30` 直接复制，不二次编码）。
默认 300 帧/段、30 帧重叠：

| 段 | start | end | 帧数 |
|---:|---:|---:|---:|
| 0 | 0 | 300 | 300 |
| 1 | 270 | 570 | 300 |
| 2 | 540 | 840 | 300 |
| 3 | 810 | 1110 | 300 |
| 4 | 1080 | 1380 | 300 |
| 5 | 1350 | 1650 | 300 |
| 6 | 1620 | 1920 | 300 |
| 7 | 1890 | 2190 | 300 |
| 8 | 2160 | 2420 | 260 |

尾段 260 帧（≥1 s）保留；`plan_chunks` 的不变式：`ends[-1]=n`、无 gap、
相邻重叠恰好 30、每帧覆盖 1–2 次；合并后 2420 帧、VMD 每轨 2420 个 dense key。
`merge.json -> merge_before.weights` 的逐帧权重和 min/max 均为 **1.0**。

切段用 ffmpeg `select='between(n,s,e)'`，逐段校验解码帧数必须等于 `e-s`；
主视频或段表变化会重切。每段是独立的 M4 run（`chunks/seg_NNN/`），
有自己的 GVHMR/手/脸/模型阶段与 manifest。

### 3.2 段间差异与对齐

GVHMR 是**逐段独立**估计的：每段的全局轨迹原点是任意的，根朝向也差几度。
实测（T5 双段探针）：重叠区根位置残差 ~0.44 unit（3.5 cm），根朝向差 ~1.9°，
但**位置 Kabsch 的 yaw 在几乎原地跳舞时会给出 18.9° 的伪解**（XZ 轨迹太短，
旋转不可辨识）。因此对齐只用：

1. **yaw**：根骨骼世界朝向的相对旋转绕 Y 的 twist（circular mean + spread）；
2. **平移**：重叠区根位置均值差（含 Y，吸收每段不同的 ground shift）。

yaw 左乘根局部旋转并旋转根平移；**其他局部旋转不变**。同一组对齐参数
同时用于 `before.vmd` 与 `final.vmd`，所以“默认档不改根/腿/手/脸”的审计
在合并后依然成立。

最终 9 段（si；三模型 yaw 相同）：

| 段 | yaw° | yaw spread° | 根位置残差 mean / max (unit) | 对齐后根旋转残差 mean / max° |
|---:|---:|---:|---:|---:|
| 1 | −0.794 | 1.90 | 0.661 / 1.298 | 3.25 / 5.68 |
| 2 | −0.903 | 1.72 | 0.213 / 0.600 | 2.98 / 5.04 |
| 3 | −2.798 | 0.32 | 0.319 / 0.746 | 4.84 / 7.56 |
| 4 | −1.611 | 1.52 | 0.773 / 1.045 | 3.08 / 5.26 |
| 5 | −1.849 | 0.44 | 0.218 / 0.595 | 1.83 / 3.53 |
| 6 | −0.306 | 0.53 | 0.143 / 0.441 | 3.67 / 6.02 |
| 7 | −0.065 | 0.51 | 0.405 / 1.070 | 2.40 / 3.54 |
| 8 | +4.140 | 0.99 | 0.176 / 0.413 | 3.62 / **13.04** |

- 段 8 的重叠区跨了 T2→T5 的内容硬切，yaw 均值 +4.14°、旋转残差最大 13.0°；
  这是**内容不连续**，不是对齐错误；边界 QC 用 `source_max_step_deg` 记录。
- 平移量随段累计增大（段 8 到 ~[15.3, 11.2, −15.7]）是 GVHMR 每段原点的任意性；
  对齐后根轨迹连续（见 §4）。
- 残差 max 到 1.30 unit（~10 cm）的段，靠 1 s 重叠的 smoothstep 交叉淡化吸收；
  没有硬切。

### 3.3 合并

- 重叠区权重 `smoothstep((i+0.5)/O)`，逐帧归一化；四元数 slerp、根平移 lerp；
- 合并后对每根骨做**半球连续化**（避免 q/−q 在 MMD 里走长弧）；
- morph 逐帧求值→混合→`compress_morph_keys`→同帧去重，需要时补 frame 0 的 0；
- IK 记录归一为 frame 0、4 个 IK 骨骼全 off；
- `before.vmd` 与 `final.vmd` 用同一 merge 参数；`feedback.json` 把各段回退窗口
  平移到全局帧号，ckpt sha256/模式一致性单独报告（`ckpt_mismatch/mode_mismatch` 均 false）。

合并证书（三模型一致）：53 轨、30 手指、4 IK off、无 D/helper、手指位移 0、
quat 误差 4.04–4.36e-8；morph 名都在 profile 内（长测试含 T1/T2 表情，
si/luoxi 8 个、tiflos 8 个；`怒り`/`怒り目` 按模型别名解析）。

## 4. 段边界连续性

### 4.1 判定

每个接缝取窗口 `[seam, seam+O−1]`（30 帧），和**同一片段内部**（排除所有接缝窗口
和首尾 2 帧，2136 帧）比较：

| 检查 | 上限 |
|---|---|
| jump | `max(internal step p95 ×1.5, 2°, source_max_step ×1.15)` |
| root step | `max(internal root p95 ×1.5, 0.05 unit, source_max_root ×1.15)` |
| toe step | `max(internal toe p95 ×1.5, 0.05 unit, source_max_toe ×1.15)` |
| freeze | 最长 `<0.02°` 连续帧 ≤ max(internal 最长, 1) |
| slide | 窗口脚滑/帧 ≤ max(internal slide/frame p95 ×1.5, 0.005) |

`source_*` 由**未合并**的两段在接缝附近的原始步长计算：内容硬切（拼接处、
不同动作切换）可以在源里就很大，不能算成分段缺陷；但合并**不能把它放大**
（上限仍乘 1.15）。`before world°` 只是后馈前的世界旋转步长，量纲与局部步长不同，
仅报告。

### 4.3 段级 QC 与回退

- 每段独立跑 M4 QC：**27/27 PASS**；段内 jerk 比 1.006–1.049；每段回退窗口
  0–7 个（第 1/3/4/6 段较多，内容切换附近）。
- 合并后回退窗口 **20/25/28**（si/luoxi/tiflos）；`feedback.json` 记录每个窗口的
  全局帧号、原因（jerk / arm_torso_penetration）、before/after 指标。
- **新增 arm-torso 窗口回退**的由来：luoxi 第 2 段的 arm-torso capsule proxy
  0.9084→0.9358（+0.0274 > +0.02 预算），段 QC 首轮 FAIL。把 arm-torso 纳入
  `_body_fallback` 的窗口判据后，该窗口被遮掉，proxy 回到 0.9084，段 PASS；
  luoxi 的回退窗口从 20 增到 25。这不是放松门禁，而是让回退覆盖 QC 已有的
  task-gate 指标；默认档（torso .85 / arm .2 / smooth 3）没有改。
- 代价：长视频上网络修正只在约 2/3–3/4 的窗口生效；回退是显式的，
  不能把“有回退”读成“无代价”。

## 5. 取景修复（每模型 auto-frame）

### 5.1 根因

M4 的 `render_synth.py` 只按**垂直** FOV 算距离，再补一个 `width*margin*1.2` 的
水平项。1440×2560 竖屏在 Blender AUTO fit 下：**vfov 39.6°、hfov 22.9°**，
水平方向窄得多；宽姿态（祀的大袖子、提弗洛斯的手臂）必然横向出画。
用新的投影函数回算 M4 的相机与 bbox（未加 2% pad）：max|NDC| 为
**祀 1.892、洛茜 1.280、提弗洛斯 1.704**——**三个模型都裁了**，不只是提弗洛斯。

### 5.2 修复

- `src/vtv/framing.py`：真实 `sensor_fovs`（AUTO/HORIZONTAL/VERTICAL）、
  Blender `to_track_quat("-Z","Y")` 一致的相机基、bbox 8 角透视投影；
- 二分最小距离，使所有角点 `max|NDC| ≤ 1/margin`（margin 1.15）；
- `render_synth.py` 默认 `--bbox-frames 0` **逐帧**扫描：
  短片段 `--bbox-scope clip`（全片，任何帧都不出画），长视频 `range`（渲染窗口）；
- `meta.json -> framing` 记录逐帧 `max_abs_ndc`/最坏帧/`ok`；
  `render.json -> framing_ok` 进入渲染证书，出画直接让渲染阶段失败；
- before 自动取景，after 用 `--camera-from` 复用同一相机，after 也重新做 framing 检查。

## 6. 缓存、断点、失败重跑

`manifest.json` 每阶段记录输入 sha256、配置、代码指纹、输出、耗时；
`chunks/seg_NNN/manifest.json` 是每段自己的记录。实测：

| 操作 | 结果 |
|---|---|
| 同命令第二次（同一组阶段） | **5.5 s**，21 个顶层阶段全部 cached（9 段 + 3 merge + 6 渲染 + 3 QC；`video30` 按 stage filter 跳过） |
| 删除 `chunks/seg_003/models/si/final.vmd` 后重跑 | **16.6 s**；只有 `chunk:003` 重跑（si feedback/QC 11.4 s），其余 8 段、3 merge、6 渲染、3 QC 全部 cached |
| 改 `src/` 后 | 所有阶段失效（代码指纹）；本轮在加 arm-torso 回退后重跑过一次全量，属于预期 |
| 主视频变化 | `chunk_plan.json` 的 `video30_fingerprint` 变化 → 自动重切段 |
| `--force-chunk N` | 绕过第 N 段的顶层记录；段内仍按 manifest 复用（真正重跑缺失/失败阶段） |
| `--stage qc` / `--stage chunks,merge,render_*` | 只跑指定阶段；用于补 QC/重渲染，不重跑上游 |

断点语义：进程中断后重跑同一条命令，已完成段打印 cached，从失败/未完成段继续；
不会重复 GVHMR、MediaPipe 或已完成的渲染。失败段在 manifest 记录
`status=failed` + error + traceback，日志在 `logs/`。

> 收尾说明：实测后把 `configs/pipeline.json -> chunking.min_tail_seconds` 接入
> `plan_chunks`（默认 1.0 s = 30 帧，与上述 9 段段表完全相同）；这是唯一在实测后
> 改动的代码路径，产物行为不变。下一次重跑会因代码指纹变化重做所有阶段。

## 9. 已知上限与失败模式

1. **段间根轨迹残差**：每段 GVHMR 独立估计，重叠残差 mean 0.13–0.77、
   max 到 1.30 unit（~10 cm）；靠 1 s 淡化吸收，不产生跳变，但长片大范围移动时
   仍应目检接缝。段 8 的 13° 旋转残差来自 T2→T5 内容硬切。
2. **回退窗口多**：长测试是 T5/T2/T1/T2/T5 拼接（含 4 个内容硬切），
   网络遇到分布外过渡；合并后 20/25/28 个 30 帧窗口被 jerk/arm-torso 回退遮掉。
   这不是“修正无效”，而是“在不确定的窗口回到 M3 输出”；代价是长视频上
   修正覆盖不全。真实连续长片的回退率需要单独测（M7）。
3. **慢动作 + 多段不支持**：`--slow-factor != 1.0` 时每段输出长度不能精确铺满
   时间轴，管线会拒绝；慢动作源请单片段跑。
4. **M3.5 secondary 代价仍在**：留出 world **+1.65°**、position **+0.141%H**；
   `secondary_ok=false`，QC/README/本文件都保留。T5 无 GT，不能用 T5 修正幅度冒充。
5. **手臂上限**：默认档手臂 gain 0.2，收益小；这是已接受的 M2.4c 上限，不在 M5 重开。
6. **手/脸覆盖低**：T5 左 L0/L1 8.3%、右 1.7%、脸 L1 5.8%；长片的 8 个 morph
   来自 T1/T2 的表情，不代表 T5；MANO/WiLoR 是 M8。
7. **取景让人物变小**：竖屏 2K 下宽袖/大翅膀角色的水平 FOV 是限制项；完整入画
   优先。接缝窗口 61 帧、range 取景，人物只占画面一部分；这是“证据完整”而非
   “特写构图”。
8. **真实视频未验证**：长视频证据来自自有 T1/T2/T5 拼接；真人/运镜仍是 M7/M8。
9. **固定机位**：`static_cam=true`；运镜需要 GVHMR VO，未验收。
10. **代码指纹会让缓存全失效**：改 `src/` 后第一次重跑会重做所有段（包括 GVHMR/渲染）；
    本轮加 arm-torso 回退后实测重跑了 9 段，~40 min。只改文档不会失效。
