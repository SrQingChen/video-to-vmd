## 2. Multi-HMR（入选）

### 2.1 许可与权重

- 代码/权重：`LICENSE.txt` 为 **NAVER Multi-HMR Non-Commercial License**
  （研究/非商业；不得商用、不得以不同条款再分发）。`model.py` 文件头另写
  “CC BY-NC-SA 4.0”，两者都指向非商业研究使用。本项目默认 research profile
  已经是非商业，因此可用；商用需替换 backend。
- 官方权重：
  - `https://download.europe.naverlabs.com/ComputerVision/MultiHMR/multiHMR_896_L.pt`
    （1,286,462,544 B）；
  - `.../multiHMR_672_L.pt`（1,272,555,601 B）；
  - README 同时给 `huggingface.co/naver/multiHMR_896_L` 官方页面。
- 依赖：`torch`（本机 2.3.0+cu121）、`torchvision`、`timm`、`smplx`、`roma`、
  `pyrender/trimesh/pyglet`（仅 import 需要；本 benchmark 不渲染）、
  DINOv2 通过 `torch.hub` 加载。SMPL-X neutral 使用仓库已有
  `body_models/smplx/SMPLX_NEUTRAL.npz`。
- Windows：纯 PyTorch，无 CUDA 扩展编译；本机可直接跑。`torch.hub` 的
  GitHub 解析在弱网下会失败，`scripts/mh_infer.py` 已改为读本地
  `~/.cache/torch/hub/facebookresearch_dinov2_main`。

### 2.2 实测（RTX 4060 Laptop 8GB，batch=1，fp16 autocast）

| 项 | 896_L |
|---|---|
| 峰值显存 | **3.44–3.47 GB**（`torch.cuda.max_memory_allocated`） |
| R2 三机位推理 | median **449–515 ms/帧**（front 507、3/4 510、side 449） |
| T5 推理 | median **227 ms/帧**（242 帧，全程） |
| 输入 | 896×896，等比缩放+黑边填充；K 用实际相机 FOV |
| 输出 | `rotvec` 53×3（root + 21 body + 15 左手 + 15 右手 + jaw）、betas、transl_pelvis |
| 检测 | `det_thresh=0.3` 时 front 7/250、side 16/250 漏检；`0.1` 时三机位/T5 全部有效 |

**检测注意**：`det_thresh=0.1` 下 front/3-4/side 分别有 10/7/7 帧检出 >1 人，
T5 有 17/242 帧 >1 人；脚本取 detector score 最高者。R2 的时序尖峰帧
（如 front 92/93）在 `num_people=1` 时也出现，说明尖峰来自模型本身的
body_pose 左右臂翻转，不是多人选择。

### 2.3 与 GVHMR 的输入差异

- Multi-HMR 是**单帧独立**模型，输出 camera-space SMPL-X；GVHMR 是视频模型，
  带时序平滑和 global trajectory。两者的 body_pose 都是 SMPL-X 标准
  parent-relative，可直接走 `run_adapter.py` 的同一适配器。
- 本 benchmark 用 `--stage-yaw 180`（SMPL-X 源），与 GVHMR 路径一致；
  body-relative 指标不使用 root/global orientation。

## 3. SAM 3D Body（不跑）

- 许可：**SAM License**（自定义；允许商用/再分发，但需附协议、禁止逆向、
  贸易管制等；不是 research-only）。
- 权重：Hugging Face **gated**：
  - `facebook/sam-3d-body-dinov3`（DINOv3-H+，840M）
  - `facebook/sam-3d-body-vith`（ViT-H，631M）
  - 需要在该 repo 点 **Request access**，通过后用 HF token 下载
    **`model.ckpt` + `model_config.yaml`**。官方 README 明确说“request access”，
    不能用非官方镜像。
- 输出：**MHR（Momentum Human Rig）**，不是 SMPL-X；repo 里只有
  `sam_3d_body/models/heads/mhr_head.py`、`metadata/mhr70.py`、
  `modules/mhr_utils.py`，没有官方 SMPL-X 转换器。要接入本项目必须先做
  MHR→SMPL-X（或 MHR→PMX）映射，属于额外研究/工程，不是“off-the-shelf”直用。
- 安装：Python 3.11 + detectron2（`git+...@a1ce2f9`，Windows 编译风险）+
  pyrender + 可选 MoGe/SAM3；比 Multi-HMR 重。
- 结论：**本轮不跑**。如果以后要试，需要用户先在 HF 申请上述 repo 的访问，
  并提供 `model.ckpt` / `model_config.yaml`；不要用第三方镜像。
  在拿到权重前，VRAM/推理时间只能按 840M/631M + detector 估算（未测）。

## 4. SMPLest-X（不跑）

- 许可：**S-Lab License 1.0**（非商业；商用需联系 S-Lab）。
- 权重：README 只提供 **Huge**：
  `pretrained_models/smplest_x_h/smplest_x_h.pth.tar`（**8.2 GB**），
  HF `waanqii/SMPLest-X`；没有 S/L 变体权重。
- 8GB：**权重文件本身 8.2GB**，已超过 8GB 显存；即使 fp16/分块也需要
  官方未提供的改动，且 ViT-H + 训练/推理激活会进一步吃紧。
- 安装：`scripts/install.sh` 用 conda + **PyTorch 1.12.0 + cu113**，
  `apt-get install libosmesa6`、`pyopengl==3.1.4`，是 Linux/conda 路线；
  Windows 需要自己重写安装。
- 结论：**本轮不跑**；不是 8GB 单卡可用的 2–3 天 spike。

## 5. WHAC（不跑）

- 许可：**S-Lab License 1.0**（非商业）。
- 权重/依赖：WHAC 的 `whac_motion_velocimeter.pth.tar` + **SMPLest-X
  pretrained（Huge 8.2GB）** + DPVO `pretrained_models/dpvo.pth`；
  安装要 `git clone --recursive`，DPVO 有自己的编译/权重。
- 输出：世界系 SMPL-X + 相机轨迹 + 手；对本轮的 **body-relative 手臂**
  不是必需，且它把 SMPLest-X 的 8GB 瓶颈原样继承。
- 结论：**本轮不跑**；等 SMPLest-X 在 8GB 上可行再谈。

## 6. 边界与后续

- 本盘点没有下载 SAM 3D Body/SMPLest-X/WHAC 权重；没有使用非官方镜像。
- 没有改默认管线：仍是 `cleanup+ik`；Benchmark 只写 `outputs/bench/external/`。
- 选型只影响“是否值得继续投入”；benchmark 结论见下一份报告：
  **Multi-HMR 在 R2/T5 上均未优于 GVHMR 基线，更远差于 M2.4c arms BA**，
  因此不集成，转 M2.5/M3/M4。
- 若未来要补 SAM 3D Body：先解决 HF 访问 + MHR→SMPL-X 映射；若未来显存
  升级到 16GB+，可再评估 SMPLest-X/WHAC。
