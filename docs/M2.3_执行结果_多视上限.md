## 1. 结论先行

| 项 | 结果 |
|---|---|
| 单视常量 swing（M2 已有） | 前视手臂世界角 **52.90→49.59°**；3/4 **63.40→61.27°**；侧面 **102.62→100.42°** |
| 共享 canonical 姿态（前视+3/4） | 前视 50.33°（比单视**差** 0.74°）；3/4 **60.26°**（比单视好 1.01°） |
| 共享 canonical 姿态（三机位） | 前视 50.23°；3/4 **59.81°**（最好，仍只比基线好 3.59°）；侧面 **99.60°** |
| 目标（再降 ≥10°） | **未达到**：前视最好只有 −3.31°，3/4 最好 −3.59° |
| 自由共享绝对姿态（无约束） | 需要 **61–65°/关节**、3D 位移 **5% 身高** 才能把 2D 降 25% → 被信任域拒绝 |
| 诊断 | 三视角的 2D 约束**互相不一致**：每个视角的 GVHMR 全局朝向各有误差（M1.5：前视 13.4°/3-4 35°/侧 84.4°），共享同一个局部姿态无法同时满足 |
| 结论 | **“多视+固定 GVHMR 根”不是 10° 的解法**；要继续多视必须联合估计每视角根朝向/相机（bundle adjustment），否则只会互相拖累。下一步应转向 M2.4 目标约束（结构后馈），不要再靠 2D 加项。 |

**一句话**：把三个机位的 2D 放在一起拟合，最多少修 1–1.5°（3/4、侧面），前视甚至更差。
不是优化器不行，而是**三个视角的 2D 证据在固定根朝向下互相矛盾**；而 2D 方向本身对
手臂深度的敏感度只有 3–5°，所以单靠 2D（哪怕三视角）到不了 10°。

## 2. 实验设置

- 三个合成机位：`outputs/gvhmr/R2fix_{front,three_quarter,side}/gvhmr_result.npz`
  （同一段 R2 动作、同一 GT，各自独立跑 GVHMR）。
- 每个视角保留自己的：`K_fullimg`（相机）、`smpl_params_incam/global_orient`+`transl`
  （根）、`betas`（体型）、ViTPose COCO-17 关键点（`preprocess/vitpose.pt`）。
- 共享的只有 **canonical 手臂 `body_pose`**：`body_pose` 是相对父骨的局部旋转，
  与相机/根无关，所以“共享 body_pose + 各自根”正是“同一角色、三个相机”的表述。
- 两种参数化：
  1. `--mode const`（与 M2 阶段可比）：每视角 `body_pose = 自己的逐帧手臂 + 同一个常量 delta`；
  2. `--mode perframe`（真正的上限）：逐帧共享一个**绝对**手臂姿态（三视角共识）。
- 损失：每个视角的置信度加权、bbox 归一的鲁棒 2D 肘/腕残差 + `λ3d`（相对该视角 GVHMR
  手臂的 3D 位移）+ `λpose`（常量 delta 幅度）+ 可选时域平滑；`LBFGS`。
- 信任域（与 M2 相同）：2D 中位改善 ≥3%、单关节修正 ≤15°、平均 3D 位移 ≤2.5% 身高。
- 评价：写各视角 npz（两处 `body_pose`）→ `run_adapter.py` → `closed_loop.py` →
  手臂世界角（上臂/前臂/手三个世界朝向的均值）、局部角、位置、jerk。

实现：`src/vtv/multiview.py`、`scripts/refine_multiview.py`。

## 5. 为什么达不到 10°（诊断）

1. **2D 方向对手臂深度的敏感度只有 3–5°**（M2 §4.2 已测：前视上臂 2D 方向残差 3–5°，
   而 3D 上臂误差 19–25°）。因此**即使 2D 拟合完美，也只能把 3D 方向移动个位数度**。
   这解释了为什么单视 52.90→49.59、三视最多 49.6–50.3：2D 证据的信息量就到这。
2. **多视本应补深度，但三个视角的根不一致**：`global_orient` 的全局朝向误差
   前视 13.4°、3-4 35°、侧面 **84.4°**（M1.5 §4.3）。共享同一个局部姿态时，
   侧面那条约束会把姿态往错误方向拽；优化器要么放弃（const 模式，只修 1°），
   要么把手臂甩出去 60°+ 换取 2D 下降（perframe 模式，信任域拒绝）。
   这是**实验得出的硬结论**，不是调参问题：`front+3/4` 与三视的 2D 改善上限被拉低，
   而前视的世界角反而比单视差。
3. **共享绝对姿态没有意义**：三个视角的 GVHMR 手臂逐帧姿态本来不同，
   强制共享一个绝对姿态等于要求“同一段动作在三个相机下手臂一模一样”，
   这只有在根/相机都正确时才成立；当前不成立。

**要点**：多视不是“再加一路 2D 就好”，而是**联合标定问题**（每视角根朝向/相机 + 一个
canonical 姿态的 bundle adjustment）。在固定 GVHMR 根的前提下，多视证据是**互相矛盾**的。

## 6. 这对后续意味着什么

1. **不要再往 2D 加项**（单视或三视都一样）：2D 方向的信息量 3–5°，已经用尽；
   `M2` 的 2D 阶段是 opt-in，M2.3 的多视共享 delta 也不该进默认管线。
2. **要突破手臂，只有两条路**：
   - **结构后馈 / 目标约束（M2.4）**：关节限位、twist 限位、胶囊自交、穿地、接触；
     这些是 3D 结构约束，不依赖像素深度。M2 的局部角是 twist 分布差（M1.5 §4.5），
     世界角/位置是更好的判据；先在目标模型上把“不可能姿态”排除，再看手臂世界角。
   - **联合根/相机估计**：把每视角的 `global_orient`（至少 yaw）作为自由变量，
     用三视角 2D + 骨长/关节限位联合求解。这是“多视真正能提供深度”的前提，
     工作量与风险都高于 M2.4，建议排在结构后馈之后或并行小规模验证。
3. **不要先训网络**：教师信号（3D 残差/约束）还不稳定，训练只会把当前偏差固化。
4. **不要用侧面世界角做跨机位门禁**（本次侧面 99.6 vs 102.6 的读数含 84° 根 yaw 误差，
   不能横比）；前视/3-4 世界角只在同机位内比较。

## 7. 交付物

| 路径 | 内容 |
|---|---|
| `src/vtv/multiview.py` | 共享 canonical 手臂 `body_pose` 的联合拟合（`const` / `perframe`）、信任域、npz 写出 |
| `scripts/refine_multiview.py` | CLI（`--npz view=path ...`、`--mode`、`--joints`、`--lam3d`） |
| `outputs/m2/multiview/const_{front,front_three_quarter,front_three_quarter_side}/` | 三个子集的 npz + `report.json` |
| `outputs/m2/multiview/all/` | perframe 无约束上限（被信任域拒绝，保留作证据） |
| `outputs/m2/multiview_eval/<subset>/<view>/metrics.json` | 各变体的闭环指标 |
| `outputs/m2/multiview_eval/<subset>/<view>_2d.vmd` | 各变体的 VMD（23 轨、IK off） |

复现：

```bash
cd /e/zcodeAI项目/视频转VMD
source .venv/Scripts/activate

# 单视（应复现 M2 的 35.06→23.07 px、10.03°）
python scripts/refine_multiview.py --npz front=outputs/gvhmr/R2fix_front/gvhmr_result.npz \
  --kp front=outputs/gvhmr/R2fix_front/preprocess/vitpose.pt \
  --mode const --joints upper --out outputs/m2/multiview/const_front

# 三视共享 delta
python scripts/refine_multiview.py \
  --npz front=outputs/gvhmr/R2fix_front/gvhmr_result.npz \
        three_quarter=outputs/gvhmr/R2fix_three_quarter/gvhmr_result.npz \
        side=outputs/gvhmr/R2fix_side/gvhmr_result.npz \
  --kp front=outputs/gvhmr/R2fix_front/preprocess/vitpose.pt \
       three_quarter=outputs/gvhmr/R2fix_three_quarter/preprocess/vitpose.pt \
       side=outputs/gvhmr/R2fix_side/preprocess/vitpose.pt \
  --mode const --joints upper --out outputs/m2/multiview/const_front_three_quarter_side

# 接 adapter + 闭环
python scripts/run_adapter.py --npz outputs/m2/multiview/const_front_three_quarter_side/front.npz \
  --model si --out outputs/m2/multiview_eval/front_three_quarter_side/front_2d.vmd
python scripts/closed_loop.py --gt outputs/gt/si_R2_safe.vmd \
  --pred outputs/m2/multiview_eval/front_three_quarter_side/front_2d.vmd --model si \
  --out outputs/m2/multiview_eval/front_three_quarter_side/front
```
