# M3 开发指导：手部 + 表情

> 日期：2026-10-27。工作目录：`E:\zcodeAI项目\视频转VMD`。
> 前置：M0–M2.5 v0.1 已完成；身体管线默认 `cleanup+ik`；手臂精度上限已接受。
> 本轮目标：**手部 + 表情从无到有**，可见片段自然，不可见片段自然降级；不碰手臂/身体研究。
> 质量优先，RTF 不作为门禁；离线可以慢，但不能抽搐、不能错骨、不能破坏身体 VMD。

---

## 1. 当前状态

- VMD 目前只有 **23 根身体轨 + 4 个 IK off**；没有手指、没有表情 morph。
- 三套模型都有完整手指骨（`profiles/*.json` 的 `finger_map`，左右各 15 根，共 30 根）
  和表情 morph（祀/洛茜 41、提弗洛斯 64；常用 21 个）。
- `src/vtv/mmd/writer.py` 已支持 `morph_frames`；`parse_vmd` 也能读 morph。
- `src/vtv/canonical_body.py` 目前只有 22 身体关节，手只到 `hand_l/hand_r`；
  M3 需要新增**手指层**（15/手）和每模型手指映射。
- 手/脸模型尚未下载；不要用非官方镜像，先核实许可。

## 2. 目标与验收

### 2.1 必须做到

1. T5 可见手片段：手指有合理弯曲/张开/指向，手腕不翻转，左右手不串；
2. T5 可见脸片段：眨眼、口型、基本表情自然；不持续抽动；
3. 不可见/低置信片段：自然 fallback（微屈手、中性脸 + 程序化眨眼），不冻结、不跳变；
4. 三模型 VMD 都保留手指/表情轨；骨名/morph 名按 profile，不硬编码；
5. 不破坏已有 body VMD：身体 23 轨不变，IK off，不写 D/helper；
6. 渲染走 `render_synth.py` bake；D 链 0/0、828 骨 verify 通过；
7. 人工修正只允许个别片段。

### 2.2 分级（必须实现）

| 级别 | 条件 | 输出 |
|---|---|---|
| **L0** | 手部 3D 模型高置信（检测+时序稳定） | 完整手指局部旋转 |
| **L1** | 2D 手关键点可见但 3D 不稳 | 2D 角度 + PMX 手指 IK/几何约束 |
| **L2** | 只有手腕/身体，手部不可见 | 程序化微屈手 + 手腕跟随身体；不造复杂手势 |
| **L3** | 完全不可见/检测失败 | 中性手 + 极轻弯曲；平滑过渡 |

脸部同理：L0 blendshape；L1 2D 眼/嘴几何；L2 眨眼/口型程序化；L3 中性 + 眨眼。

### 2.3 合成闭环在 M3 的用法

“动作→视频→识别→动作比对”在 M3 里只用于**开发期评测/回归**，不是运行时输入：

1. 用 R1/R2/R3 的 GT VMD（必须含手指/表情轨）→ 三模型渲染；
2. 身体用固定全身机位；手/脸加固定近景机位（或高分辨率全身裁剪）；
3. 跑 GVHMR→adapter→cleanup+ik→M3 手/脸；
4. 和 GT 比 **手指角/morph 权重/时序**，不比像素/剪影；
5. T5 没有 GT，只做视觉/fallback/人工检查；
6. M3.5 再把这条闭环变成数据引擎和教师，训练后馈网络。

## 3. 手部方案

### 3.1 先做 M3.0 可行性审计（0.5–1 天）

在 T5 上抽 30–50 帧（含手在脸前、快速挥动、遮挡、小尺寸）：

- 统计手部可见帧比例、手框像素尺寸、左右手检测率；
- 试 **WiLoR** 和 **MediaPipe Hands** 各 10 帧，记录：
  - 检测率、21 点稳定性、MANO/3D 是否可用、单帧耗时；
  - 在动漫手上的失败模式（漏检、左右手互换、手指融合）。
- 结论写成 `docs/M3.0_手部可行性.md`，再决定主方案。
- **不要**在没有审计的情况下直接集成大模型。

### 3.2 主方案选择

推荐顺序：

1. **WiLoR（首选）**：YOLO 手检测 + MANO 3D，in-the-wild 鲁棒，8GB 可跑；
   需要 MANO 权重/许可，官方渠道下载；不要非官方镜像。
2. **HaMeR（质量备选）**：MANO 3D 手，精度高但更重、依赖更多；如果 WiLoR
   在动漫手上失败，再用 HaMeR 对照。
3. **MediaPipe Hands（无 MANO 兜底）**：21 个 2D 点，CPU 可跑；没有 3D 手指，
   需要 PMX 手指 IK/角度启发；作为 L1/无权重环境 fallback。
4. **OSX / SMPLer-X 手分支**：质量潜力高但依赖重、8GB 紧张，不作为首选；
   只有前三个都不行时再评估。

**不要**为了“最强模型”阻塞 M3：先用 MediaPipe 把 VMD 手指轨和 L0–L3 管线打通，
再换 WiLoR/HaMeR 提升质量。

### 3.3 预处理与检测

- 从身体 VMD/2D 证据得到手腕位置；用身体 bbox 扩边生成手 crop；
- 左右手分别检测，禁止只靠图像左右猜；用身体左右手腕位置消歧；
- 手框跟踪：IoU/中心距离 + 置信度 + 左右手约束；丢失 2–3 帧用上一帧位置扩边重试；
- 低置信不硬写，进入 L1/L2；
- 记录每帧 `hand_conf_l/r`、`hand_bbox`、`landmarks2d`、`mano_params`。

### 3.4 3D 手 → PMX 手指

- 输入：MANO/SMPL-X 手关节（每手 15 个手指关节 + 手腕）；
- 统一到 canonical 手坐标系：手腕朝向来自身体 `hand_l/r`，手指局部旋转相对手腕；
- 用与身体相同的镜像/`stage_yaw` 约定，不要另起一套；
- 每模型手指映射来自 `profiles/*.json`：
  - `thumb0/1/2`、`index1/2/3`、`middle1/2/3`、`ring1/2/3`、`pinky1/2/3`；
  - 全部 30 根；`finger_missing` 为空，但代码仍要按 profile 查；
- 只写**局部旋转**，不写手指位移；不写 `手捩/腕捩` helper；
- 手指骨长差异：只保留旋转，不做缩放；极端伸展用限位钳制；
- 输出 VMD：身体 23 轨 + 手指 30 轨 + 4 IK off；morph 另写。

### 3.5 L1（2D + IK）与 L2/L3

- L1：用 21 个 2D 点 + 手骨长，求每根手指的弯曲角（MCP/PIP/DIP）；
  只解屈曲/侧摆，不做无约束 3D；置信度低时降权；
- L2：手腕跟随身体，手指保持自然微屈（例如 10–20°），不做抓握/指向；
- L3：中性手，轻微弯曲；用 3–5 帧 smoothstep 从 L0/L1 过渡，避免跳变；
- 所有级别都做时序平滑和速度限幅；不要逐帧硬切。

### 3.6 手部验收

- T5 三模型 2K 渲染：手在脸前、挥手、快速动作不抽搐/不反关节/不穿脸；
- 左右手不互换；手指不整根翻转；手腕不 candy-wrapper；
- 可见手片段 L0/L1 占比、L2/L3 占比报告；
- 观测帧不改身体；VMD 23+30 轨；D 链 0/0；无 scale warning；
- 人工修正 ≤ 个别片段。

## 4. 表情方案

### 4.1 输入

- 首选 **MediaPipe Face Landmarker**（478 点 + 52 blendshapes，CPU/GPU 均可）；
- 若动漫脸检测失败，用 2D 眼/嘴几何（EAR、嘴开合、嘴角）做 L1；
- 不做身份/像素比对；只用 landmark/blendshape/时序。

### 4.2 每模型 morph 别名

从 `profiles/*.json` 的 `morphs` 生成别名表，至少覆盖：

| 语义 | 祀/洛茜 | 提弗洛斯 |
|---|---|---|
| 眨眼 | まばたき | まばたき |
| 左/右眨眼 | ウィンク/ウィンク右 | ウィンク/ウィンク右 |
| 笑 | 笑い/にこり | 笑い |
| 惊讶 | びっくり | びっくり |
| 怒 | 怒り | 怒り目 |
| 困 | 困る | 悲しい目 |
| 口型 a/i/u/e/o | あ/い/う/え/お | あ/い/う/え/お |

- 不假设三模型 morph 同名；按 profile 的 `morph_name/name_en` 匹配，匹配不到就跳过；
- 只写模型实际存在的 morph；不要写入不存在的名字（VMD 会变成无效轨）。

### 4.3 映射与平滑

- `eyeBlinkLeft/Right` → 眨眼/单眼 wink；`jawOpen` → あ/お；`mouthSmile` → 笑い；
  `mouthPucker` → お；`mouthFrown` → 困る/悲しい目；
- 强度 0–1，按语义组合；同一帧最多 3–4 个 morph，避免叠加爆形；
- 3 帧中值/低通 + 斜率限制；表情切换用 2–4 帧过渡；
- 眨眼：检测到就跟随；检测不到用程序化眨眼（间隔 3–6 秒、持续 0.1–0.15 秒、
  随机抖动），不要固定节拍；
- 口型：优先 blendshape；不可用则用嘴部几何；不可用则中性；
- 表情与身体独立，不因身体后馈改变。

### 4.4 表情验收

- T5 三模型 2K：眨眼自然、口型不抽搐、表情不长期漂移；
- 低置信片段走 L1/L2/L3，不出现“半张脸持续扭曲”；
- morph 名按 profile 存在；VMD 读取回放正常；
- 每模型 morph 覆盖率/fallback 比例报告。

## 6. 评测与门禁

- **T5 三模型 2K**：手/脸可见片段自然；不可见片段 fallback 平滑；
- VMD：身体 23 + 手指 30 轨；IK off；morph 名存在；无 D/helper；
- 渲染 bake：D 链 0/0、828 骨 verify <2e-6、scale warning 0；
- 手指/表情不改变身体轨（观测帧逐帧回写）；
- 人工修正 ≤ 个别片段；
- 报告：L0/L1/L2/L3 帧比例、手检测率、morph 覆盖率、失败片段清单。

---

## 7. 不要做

1. 不要为了手/脸回头改手臂/身体后馈；
2. 不要用非官方镜像下载 MANO/手模型权重；先核实许可；
3. 不要把 MANO/SMPL-X 的坐标直接写进 VMD；必须过 canonical/adapter；
4. 不要写手指位移、D 链、helper 到 MMD VMD；
5. 不要在没有检测的帧硬造复杂手势；L2/L3 自然 fallback 是正确结果；
6. 不要逐帧硬切/无平滑；不要用像素/剪影比对；
7. 不要 commit，除非用户明确说。
