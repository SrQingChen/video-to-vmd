## 2. 做了什么

### 2.1 目标空间审计（GT-free）

`src/vtv/arm_prior.py`：

1. **手掌铰链线**：从目标 PMX 自身的手指 rest 骨（`左/右中指１`、`人指１`、`薬指１`）
   构造 hand frame，取 palm normal 作为肘铰链线。它由模型几何决定，不需要 GT，也不写死
   “人类肘轴”；si 的左右铰链线镜像误差 <1°，与上臂 rest 方向近似垂直（偏差 ~4°）。
2. **肘铰链审计**：用 `L = inv(G_upperarm) · G_forearm` 的旋转轴；
   纯铰链应有一条**时不变轴**。报告轴 scatter、平均屈曲角、轴与手掌铰链线的偏差。
3. **swing/roll 分解**：世界四元数误差 `qe = q_gt · conj(q_pred)` 分解为
   `swing`（把预测骨方向转到 GT 方向的短弧）和 `roll`（绕骨轴的残差）。
   **swing 会移动子关节，roll 不会**；两者必须分开看。
4. **PMX 胶囊**：用模型自带 rigid body（shape 0 球 / 2 胶囊，每个语义骨取第一个身体代理）
   做手臂-躯干、左臂-右臂的逐帧穿透。这里修正了 M2.4 早期诊断的一个变换 bug：
   PMX rigid body 的 `pos` 是**模型空间**，必须先减去骨骼 rest 位置再乘 `world_q`；
   之前重复平移把间距放大成 18 unit。修正后 GT 的肘-胸中位间距 ~0.2 unit、
   front 预测左肘中位**穿进上胸 0.58 unit**、最深穿头 1.07 unit，与目视一致。
5. **肩/腕审计**：上臂方向在 chest frame 的分量、腕局部旋转角、腕屈曲角。
   本轮没有把“肩限位”写成硬约束：R2 的手臂在折叠位，宽限位（例如
   “上臂不指向躯干内部”）已经被胶囊覆盖，额外锥限位只会增加假阳性。

### 2.2 低维目标约束 + 2–3 轮微反馈

`resolve_self_intersections`：

- 每轮评估 PMX 胶囊，找**超过 `pen_tol=0.25 unit`** 的最深穿透；
- 只允许**肩部 3 DOF** 修正：在碰撞点处求最小旋转 `ω = (r × Δ)/|r|²`，
  把手臂推开 `min(max_disp, depth − pen_tol)`；肘/腕局部旋转**完全不动**，
  所以肘铰链和手臂平面被保留；
- 本轮信任域：累计肩旋转 ≤ **8°**（默认 12°；不是每轮 8°，否则 3 轮变 24°）、
  单轮位移 ≤0.3 unit（默认 0.6）、时间 3 帧平滑；
- 2–3 轮 evaluate → correct → re-evaluate；
- 自检：非手臂轨 1e-9 不变、骨长 1e-6、IK 记录不变、23 轨、contact/腿完全不变、
  臂-躯干穿透不增（臂-臂允许 ≤ pen_tol+0.02 的小重叠）、累计修正 ≤ cap。

**验收门槛**（比“穿透变小”更严）：如果输入存在 >`pen_tol` 的穿透，修正后必须把
最深穿透降低 **max(0.05, 25%·(depth−tol))**；否则视为“动了姿态但没修好”，拒绝回退。

### 2.3 解剖 arm prior（实验，默认不进管线）

`project_hinge`：把肘局部旋转轴投影到手掌铰链线，保持屈曲角（`keep_flexion`），
逐帧变化 ≤15°。这是 M2.4 的“肘铰链/手臂平面”先验实现。
它在 R2 上**只改 roll**：世界角降了，前臂方向反而变差。默认 CLI 不选它；
`--mode hinge --force` 只用于实验记录。

### 4.1 为什么穿透方向不是 GT 误差方向

`front`，把每个穿透对的推出方向与 GT 关节误差向量做点积（+1 = 完全同向）：

| 部位 | 穿透帧数 | 深度中位 | GT 位置误差中位 | 推出方向·GT 误差 cos（中位） |
|---|---:|---:|---:|---:|
| 左肘 | 233 | 0.606 | 1.875 | **+0.04**（正交） |
| 右肘 | 67 | 0.301 | 2.052 | **−0.73**（反向） |
| 左手 | 34 | 0.152 | 3.027 | **−0.90** |
| 右手 | 46 | 0.179 | 2.099 | **−0.51** |

即：预测的左肘穿进胸腔/头，确实是视觉问题；但沿“推出”方向移动并不能把它移向 GT，
右臂/手甚至会远离 GT。目标空间约束只能保证“不穿模”，不能提供“该往哪走”的深度信息。

## 6. 为什么 10° 目标不可达（定量）

### 6.1 2D 能看到多少

`scripts/probe_arm_info.py`（GT 只读），front/3-4：

| view | 侧 | 2D 上臂方向残差（中位/p90） | 2D 前臂方向残差 | 3D 上臂方向误差 | 3D 前臂方向误差 | 上臂深度估计 | 前臂深度估计 |
|---|---|---:|---:|---:|---:|---:|---:|
| front | L | 3.4 / 9.5° | 8.6 / 20.8° | 19.3° | 25.1° | 18.9° | 23.6° |
| front | R | 2.6 / 6.9° | 8.5 / 25.4° | 25.4° | 22.2° | 25.3° | 20.5° |
| 3/4 | L | 6.4 / 15.8° | 11.0 / 31.2° | 44.7° | 42.5° | 44.2° | 41.1° |
| 3/4 | R | 4.4 / 13.4° | 11.3 / 49.7° | 18.6° | 42.7° | 18.1° | 41.2° |

2D 方向误差只有 **3–11°**，而 3D 方向误差 **19–45°**；差值就是**深度分量**。
即使 2D 拟合完美（单视或三视、根已知），它也**只能修 3–11° 的 in-plane 分量**，
到不了 10° 的 3D 改善；前视上臂还有 19–25° 的深度误差，3/4 左臂有 44°。

### 6.2 绕上臂轴的 roll 上限（oracle）

对每一帧，绕预测上臂方向滚动前臂，取最接近 GT 前臂方向的 roll（这是任何
“手臂平面/roll 先验”的**上限**）：

| view | 侧 | 修正前前臂方向误差 | oracle roll 后残余 | oracle 增益 | 需要的 roll 中位（p5/p95） |
|---|---|---:|---:|---:|---:|
| front | L | 25.1° | 18.1° | **7.1°** | +18.1°（−4.6/+46.2） |
| front | R | 22.2° | 16.6° | **5.5°** | −4.9°（−43.4/+18.0） |
| 3/4 | L | 42.5° | 24.8° | **17.8°** | +34.7°（−7.9/+49.3） |
| 3/4 | R | 42.7° | 26.0° | **16.7°** | +44.4°（−25.2/+74.2） |

- front 的 oracle roll 只能拿回 5.5–7.1°，残余 16.6–18.1°，**正好等于上臂方向误差**
  （19.3/25.4°）；即前臂方向误差基本被“上臂方向错”锁死，roll 不是 front 的主因。
- 3/4 的 oracle roll 能拿回 16–18°，但需要逐帧 ±30–74° 的 roll，这不是一个常数
  rest-roll 修正；我们扫描了 0–180° 的**常数** roll，最优只降 0.7°（`front`），
  所以“改 twist/rest-roll 约定”不能替代它。
- 任何静态解剖先验（肘铰链线、肩限位、手臂平面）都不知道这个逐帧 roll；
  能提供它的只有**学习到的 3D arm prior** 或**真正的多视深度**。

### 6.3 多视 3D 融合也不行

把三视角 GVHMR 的 `body_pose`（视角无关的局部量）做加权四元数融合，再各自 adapter +
闭环（21 组权重扫描，三视 `body_pose` 四元数融合）：

| 方案 | front 手臂世界角 | 3/4 手臂世界角 |
|---|---:|---:|
| front 单视（baseline） | 52.77 | 63.33 |
| 最好权重（front 0.5 / 3-4 0.3 / side 0.2） | **50.77（−2.0）** | 66.08（**+2.75**） |
| M2.3 共享 2D const（最好） | 50.23（−2.5） | 59.81（−3.59） |
| 目标 | ≤42.90 | ≤53.40 |

三视 3D 融合不降反升（3/4 最好也 +2.75°），说明三视角的 **body_pose 误差高度相关**，不是独立噪声；
固定根的多视 2D 已在 M2.3 证明互相矛盾。只有在**联合估计每视角根/相机 + 真实深度**
（bundle adjustment）时，多视才可能提供新的深度信息；而 2D 方向本身只有 3–11°，
BA 的上限仍受这个信息量约束。

补充检查：用 `outputs/synth/si_R2_fixed/*/meta.json` 的**真值相机外参**直接三角化
ViTPose 原始关节也不可行——渲染角色的关节中心与 PMX 骨原点有系统偏差（前视肩/肘
约 70–100 px），三角化后的 3D 位置误差到 7–11 unit（0.58–0.92 m），上臂/前臂方向
误差反而更大。多视要有效必须联合 **body model + 相机 + 每视角根**，不能把关键点
直接当骨点；其 2D 残差上限仍是 §6.1 的 3–11°。

### 6.4 目标约束为什么帮不上

1. **肘已经是纯铰链**：轴 scatter 4–9°，没有“侧向反折”可修；
2. **肩限位不违反**：R2 的折叠手臂在宽限位内；加锥限位只会造出假阳性；
3. **手臂平面/铰链线**：与手掌轴差 10–20°，投影它只改 roll（§5）；
4. **胶囊自交**：front 的左肘穿胸/头是真的，但推出方向与 GT 误差正交或反向（§4.1），
   修正只会让 3D 姿态变差；GT 自身也允许 ~0.2 unit 的接触，硬推到 0 会过约束；
5. **腕**：COCO-17 只有腕位置，没有手掌/手指方向；GT 腕屈曲 40–44°，预测 8–15°，
   这是一个**不可观测**的自由度，不能靠目标约束定。

因此，10° 的目标不是“再调一下限位/胶囊”能解决的，而是**证据缺口**：
单目 2D 看不到手臂深度，目标空间约束看不到“该往哪走”。诚实的结论是：
**在现有前馈 + 2D + 目标几何下，front/3-4 的手臂世界角不能可靠再降 10°**。

## 10. 下一步

**不要**把 `hinge` / `constraints` 默认打开；`cleanup+ik` 保持管线默认。

要达到 front/3-4 世界角 ≥10° 的下降，只有两条有信息量的路：

1. **3D arm prior（学习型）**：用一个在 AMASS/SMPL-X 手臂上训练的 pose prior
   （或上肢专用的 3D 方向/roll 先验）给单帧提供深度/roll；这是“先验”，不是
   “用本文的弱教师训后馈网络”。需要模型权重/数据集，当前仓库没有；
2. **联合根/相机 BA（多视真实深度）**：每视角 `global_orient`（至少 yaw）+ 相机
   作为自由变量，用三视 2D + 骨长/关节限位联合求解；M2.3 已证明固定根不行，
   但 BA 的上限仍受 2D 方向 3–11° 的信息量约束，需要真实外参/标定，风险高于 1。

同时建议**修改门禁口径**：

- 手臂指标拆成 **swing（骨方向）** 与 **roll（绕骨轴）**；世界角 geodesic 保留为报告，

- 跨机位只比局部角/位置；侧面的世界角永远不参与跨机位门禁；
- 若坚持 geodesic 世界角 -10° 作为硬门禁，必须同时要求 swing 不升、3D 位置不升、
  自交不增；在这些约束下，本轮所有候选都不合格，且现有证据无法达标。

**髋高实验**仍然独立：M2.2 的 0.14 unit 残余在腿长之外，任何根骨 Y 修正都要有穿地约束
并单独报告，不与本轮的 arm/IK 混在一起。
