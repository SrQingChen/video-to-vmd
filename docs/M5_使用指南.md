# M5 使用指南：长视频、自动取景与发布候选

> 适用版本：M5（2026-10-28；M6 追加 v2）。M5 原文默认 = M3.5 保守后馈；
> **M6 后默认改为 `--feedback v2`**（躯干 0.85 / 手臂 0.30 / smooth 3；
> 手、脸、根关闭），M3.5 用 `--feedback default` 切回。
> 质量优先：离线允许小时级处理；RTF 不是门禁。
> 相关：[M4 使用指南](M4_使用指南.md)（短片段基础）、
> [M5 执行结果](M5_执行结果_长视频与发布候选.md)（实测数字）。

---

## 1. M5 新增了什么

| 能力 | 说明 |
|---|---|
| 长视频自动分段 | 默认 10 s 段 + 1 s 重叠；任意长度不爆显存；每段独立跑完整管线（GVHMR→adapter→cleanup→contact IK→手/脸→反馈） |
| VMD 合并 | 每段 53 轨先对齐（根 yaw + 平移，来自重叠区），再按 smoothstep 交叉淡化；合并后仍 53 轨/30 手指/4 IK off/无 D/helper/手指位移 0 |
| 段边界 QC | 每个接缝检查跳变、冻结、根/脚步长、脚滑，和**同一片段的内部**比较；有内容硬切时用 `source_max_step_deg` 区分，不把源片段的切点算成分段缺陷 |
| 分段缓存/断点 | 每段有自己的 manifest；中断后只重跑未完成段；`--force-chunk N` 可单独重跑某段 |
| 每模型自动取景 | 用真实水平/垂直 FOV 双轴拟合（修掉 M4 的横向裁切），按全片/片段的 bbox + margin；before/after 共用同一相机并逐帧检查“没有部位出画” |
| 发布候选 | `pyproject.toml`、`check_env.py`（含 `--long`）、demo 清单、CI 轻量测试、许可/文档 |

## 3. 一条命令

### 3.1 短片段（M4 行为，≤10 s）

```bash
python scripts/run_vtv.py \
  --video testdata/T5_高速舞蹈_001/001.mp4 \
  --out outputs/m5/t5 --models si,luoxi,tiflos \
  --feedback default --render
```

视频不超过 `chunk_seconds` 时自动走单片段路径（不会产生分段开销）。
`--chunk-seconds 10` 是默认；`--no-chunk` 或 `--chunk-seconds 0` 强制单片段。

### 3.2 长视频（默认 10 s 段 + 1 s 重叠）

```bash
python scripts/run_vtv.py \
  --video outputs/m5/long/long_80s.mp4 \
  --out outputs/m5/long/run --models si,luoxi,tiflos \
  --feedback default --render
```

一条命令会：

1. 生成 30 fps 主视频（源已是 30 fps 时直接复制，不二次编码）；
2. 按 300 帧/段、30 帧重叠切段（帧精确，`select` 滤镜）；
3. 每段跑完整管线并做段级 QC；
4. 每模型对齐 + 合并 + 合并证书 + 全局 QC；
5. 渲染接缝窗口的 before/after（默认第 0 个接缝，±30 帧，2K）。

也可显式指定：

```bash
--chunk-seconds 10 --overlap-seconds 1
--render-boundary 0        # 渲染第 0/1/... 个接缝；none 关闭，回到 --frames
--boundary-half 30         # 接缝窗口半径（Blender 帧）
--force-chunk 3            # 只绕过第 3 段的顶层缓存记录（段内仍按 manifest 复用）
```

**约束**：多段 + `--slow-factor != 1.0` 会被拒绝（每段输出长度无法精确铺满时间轴；
慢动作源请单片段跑）。`--seed`/`--gt` 在多段模式下也不可用。

### 3.3 长测试视频从哪来

仓库不携带视频。用自有片段拼接（同分辨率/帧率，脚本会写 manifest）：

```bash
python scripts/make_long_video.py \
  --inputs testdata/T5_高速舞蹈_001/001.mp4,testdata/T2_中速同舞_05x/10月24日0.5.mp4,testdata/T1_慢速同舞_025x/0.25.mp4 \
  --out outputs/m5/long/long_80s.mp4 --fps 30
```

拼接处是**内容硬切**；QC 的 `source_max_step_deg` 会把它和真正的分段缺陷区分开。

## 5. 分段/合并是怎么做的

1. **切段**：在主 30 fps 视频上按 `[s, s+300)` 取段；相邻段重叠 30 帧。
   段表保证 `[0, n)` 恰好被覆盖 1–2 次，无缺帧/重复帧；尾部 <30 帧会并入前一段。
2. **每段完整管线**：GVHMR（段内独立）→ adapter（每段自己的 origin/scale/ground）
   → cleanup → contact IK → M3 手/脸 → 后馈（M6 默认 v2；M3.5 `default` 可切回）→ 53 轨 VMD。
3. **对齐**：用重叠区根骨骼的**世界朝向**求 yaw（绕 Y 的 twist）；yaw 作用到根
   局部旋转（左乘）与根平移；平移取重叠区根位置均值差。只改根，不改其他局部旋转。
   `merge.json -> chunks[i].shift` 记录 yaw/平移/残差；残差是两段对同一内容的位置差
   （T5 探针约 0.44 unit ≈ 3.5 cm，属于 GVHMR 段间全局轨迹差异，靠重叠淡化吸收）。
4. **交叉淡化**：重叠区权重 `smoothstep`（0→1），四元数 slerp、根平移 lerp；
   权重逐帧归一化。然后做四元数半球连续化（避免 MMD 走长弧）。
5. **合并证书**：合并后的 before VMD 必须仍是 53 轨/30 指/4 IK off/无 D/helper/
   手指位移 0；morph 关键帧去重并在需要时补 frame 0。
6. **后馈一致性**：`before.vmd` 与 `final.vmd` 用**同一组对齐/淡化参数**，所以
   “默认档不改根/腿/手/脸”的逐轨审计在合并后依然成立；合并后的 `feedback.json`
   把各段回退窗口平移到全局帧号。

## 6. 取景（每模型 auto-frame）

`scripts/render_synth.py` 现在：

- 用 Blender 的真实传感器/AUTO fit 计算 **hfov 和 vfov**；竖屏 2K（1440×2560）的
  水平 FOV 只有约 22.9°，M4 只按垂直 FOV 算距离，所以宽姿态会被横向裁掉；
- 对 bbox 的 8 个角做**透视精确**拟合（二分最小距离，目标 `max|NDC| ≤ 1/margin`）；
- 默认 `--bbox-frames 0`：**逐帧**扫描（短片段 `bbox_scope=clip` 覆盖全片，
  长视频 `bbox_scope=range` 覆盖渲染窗口）；M4 的 8 帧采样会漏掉宽姿态帧；
- 输出 `meta.json -> framing`：逐帧投影的 `max_abs_ndc`/最坏帧/是否在画面内；
- `render.json -> framing_ok` 进入渲染证书：有部位出画时渲染阶段直接失败，
  不会产出“看起来没问题”的证据。

before/after 仍共用同一相机（after 用 `--camera-from before/meta.json`），
after 也会重新做 framing 检查；相机只影响渲染，不影响 VMD/动作。

可用参数：`--bbox-scope clip|range`（`run_vtv.py`）；`render.bbox_frames`
（`configs/pipeline.json`，0=逐帧）；`render_synth.py --margin`（默认 1.15，
pipeline 使用默认值；直接调 Blender 时可改）。

## 7. QC 怎么读（三层）

`qc/summary.md` 给人看，`qc/summary.json` 给机器；每模型 `models/<m>/qc.json`
是完整证据。

| 层 | 内容 | 是否阻塞 |
|---|---|---|
| **task gate** | VMD 证书、GT-free jerk/脚滑/穿地/手指步长/morph 步长、根/腿/手/脸未变审计、有 GT 时的 body-relative/接触/时序、**长视频的段边界连续性** | 是 |
| **secondary** | 绝对 world-angle、3D 位置误差增量（无 GT 时引用当前反馈档的留出参考；v2 查 `report_m6_final_body03_noproxy.json`） | 否，但**必须报告** |
| **段级 QC** | 每段自己的 M4 QC（证书/稳定性/回退窗口/耗时），在 `chunks/seg_*/qc/`；顶层 summary 有 “Segment QC” 表 | 段级失败会显式列出 |

### 7.1 段边界表

`qc/summary.md -> Chunk boundaries`：

- `max step°`：接缝窗口内最大单帧局部四元数步长（所有骨）；
- `before world°`：同一窗口内后馈前**世界**旋转步长（仅报告，和局部分数量纲不同）；
- `source°`：未合并的两段在接缝处的最大步长，用于区分**内容硬切**；
- `freeze`：窗口内最长“几乎不动”连续帧数；
- `slide/frame`：窗口脚滑/帧数；
- `jump/root/toe/freeze/slide`：逐项检查和总 `ok`。

判定是**相对同片段内部**：`p95×1.5 + 绝对下限`；`source°×1.15` 也会放宽 jump 上限。
root/toe 步长同样有 `source_max_root/toe×1.15` 的源允许（内容硬切/快速踢腿不会被
算成分段缺陷），但合并不能把它放大。所以快速舞蹈不会因为绝对步长大而误报，
静音段冻结也不会被平均掉。失败会写进 `warnings` 并让 task gate 失败，不会静默。

### 7.2 回退

- 默认档只改上半身；腿/脚/根/手/脸结构上不变，QC 逐轨验证。
- 段内窗口回退（jerk/脚滑/穿地/**arm-torso 胶囊 proxy**）会在
  `feedback.json -> segments_fallback` 记录；合并后用全局帧号保留。顶层 summary
  的 “fallback windows” 是该模型的总窗口数。arm-torso 与 QC task gate 使用同一
  budget（+0.02），避免“段 QC 失败但回退没覆盖”的缝隙。
- 整段回退 `whole_clip_fallback=true` → 该段 `final=before`，合并后仍是 before。
- 手/脸步长退化 → `handface_fallback=true`（默认档不会触发）。

## 8. 缓存、断点、重跑

每个阶段（顶层和每段）都有自己的 manifest：输入 sha256、阶段配置、代码指纹
（`pipeline_code`）、输出、耗时。满足“状态 ok + 输入/配置/代码一致 + 输出存在”
才复用。

```bash
# 断点：重跑同一条命令；已完成的段打印 cached
python scripts/run_vtv.py ... --out outputs/m5/long/run ...

# 只重跑某个模型的某阶段（所有段都会跟着失效/重跑）
python scripts/run_vtv.py ... --force feedback --no-render

# 只绕过某段的顶层缓存记录（段内仍复用 manifest）
python scripts/run_vtv.py ... --force-chunk 3 --no-render

# 只补 QC / 重渲染（不重跑上游）
python scripts/run_vtv.py ... --stage qc
python scripts/run_vtv.py ... --stage render_before,render_after

# 忽略 manifest，全部重跑
python scripts/run_vtv.py ... --no-resume
```

注意：

- 改 `src/` 或关键 `scripts/` 会让所有阶段失效（包括渲染）；这是有意的。
- 只改文档/README 不会。
- `chunk_plan.json` 记录切段文件的 hash；主视频变化会自动重切。
- 删除某段的 `final.vmd` 后重跑：顶层段阶段会重跑该段，段内只有缺失阶段执行；
  合并阶段在输入字节不变时保持 cached。
- `qc/summary.json` 的 `elapsed_seconds` 是**最近一次命令**的耗时；只跑
  `--stage qc`/重渲染的补跑会把它改短。全长耗时看 `manifest.json` 的阶段秒数。

## 9. 配置（configs/pipeline.json）

在 M4 基础上新增：

| 键 | 说明 |
|---|---|
| `chunking.enabled` | 总开关（默认 true；短于一段的视频自动单片段） |
| `chunking.chunk_seconds` / `overlap_seconds` | 段长/重叠（默认 10/1） |
| `chunking.min_tail_seconds` | 尾段短于此值并入前一段（默认 1） |
| `render.bbox_scope` | `null`=自动（短片段 clip，长视频 range）；也可 `clip`/`range` |
| `render.bbox_frames` | 0=逐帧扫描（默认）；>1=均匀采样（调试用） |
| `render.boundary` | `null`=不用接缝窗口；整数=第 N 个接缝；长视频+渲染时默认 0 |
| `render.boundary_half` | 接缝窗口半径（Blender 帧，默认 30） |

**默认反馈档不要改**：`torso_gain=0.85`、`arm_gain=0.20`、`smooth=3`，
`apply_root/apply_hands/apply_face=false`。

## 10. 已知问题

1. **段间根轨迹差异**：GVHMR 每段独立估计全局轨迹，重叠区根位置残差约
   0.4–0.5 unit（3–4 cm，T5 探针）；对齐+淡化把它变成 1 s 内的平滑修正，
   QC 会报告每段 yaw/平移/残差。不是跳变，但长片大范围移动时应目检接缝。
2. **段内回退**：80.7 s 拼接测试（含 4 个内容硬切）上，合并后 20/25/28 个
   30 帧窗口被 jerk/arm-torso 回退遮掉（约 25–35% 的帧），修正覆盖不全；
   回退窗口在 `feedback.json` 和 summary 中显式列出，不隐藏。真实连续长片的
   回退率需要 M6 单独测。
3. **慢动作 + 多段不支持**：`--slow-factor != 1.0` 时每段输出长度无法精确铺满
   时间轴；请单片段跑。错误信息会提示。
4. **真实视频未验证**：M5 的长视频证据来自 T1/T2/T5 拼接；真人/运镜素材仍是 M6。
5. **固定机位假设**：默认 `static_cam=true`；运镜需要 GVHMR VO 分支，未验收。
6. **手/脸覆盖低**：T5 左 L0/L1 8.3%、右 1.7%、脸 L1 5.8%；默认不启用手/脸后馈。
7. **T5 jerk 余量**：M4 默认档 +4.8–4.9%，接近 5% 门禁；长视频分段的段级
   回退会处理超限窗口，但不要把“有回退”当成“无代价”。
8. **自动取景会让人物变小**：竖屏 1440×2560 下，宽袖/大翅膀角色的水平 FOV 是
   限制项；完整入画优先于画面占比。确需特写时用 `--bbox-scope range` 并缩短
   渲染窗口，而不是关掉 framing gate。
9. **渲染耗时**：2K 12 samples 约 1 s/帧（RTX 4060 Laptop 量级），61 帧 ×
   before/after × 3 模型约 5–6 分钟；Blender 偶发崩溃由重试覆盖。
10. **缓存与代码指纹**：改 `src/` 后第一次重跑会重做所有阶段（含渲染）；
    只改文档不会。
