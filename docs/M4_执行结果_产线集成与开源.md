## 3. 一条命令与阶段图

```bash
python scripts/run_vtv.py \
  --video testdata/T5_高速舞蹈_001/001.mp4 \
  --out outputs/m4/t5 --models si,luoxi,tiflos \
  --feedback default --render
```

```
gvhmr                  run_gvhmr.py（30 fps，static camera）
hands / face           MediaPipe 手/脸证据（三模型共享）
<model>:adapter        run_adapter.py（GVHMR npz → 目标 PMX）
<model>:cleanup        M2 选择性清理
<model>:contact_ik     M2.2 接触/腿 IK
<model>:assemble       M3 身体 + 30 手指 + morph → before.vmd
<model>:feedback       M3.5 保守残差 → after.vmd / final.vmd
<model>:render_before  2K、固定机位
<model>:render_after   同一相机（--camera-from before/meta.json）
<model>:qc             证书 + 稳定性 + 未变审计 + 穿模 + 次要代价
qc/summary.{json,md}   汇总
```

每个阶段在 `manifest.json` 记录：

- 输入文件 sha256 / size；
- 阶段配置（含 `pipeline_code` 代码指纹）；
- 输出文件哈希；
- 耗时、完成时间、seed 来源；
- 失败时的 error + traceback（`logs/<stage>.log` 保留子进程输出）。

缓存复用条件：`status=ok` + 输入哈希一致 + 配置一致 + 代码指纹一致 + 输出仍存在。
改 `src/`/关键 `scripts/` 会让所有阶段失效；只改文档不会。

## 4. 默认档的实现与安全边界

### 4.1 应用顺序

```
身体 VMD（adapter + cleanup + contact IK）
  + M3 手/脸（53 轨 + morph）
  → 网络：证据特征（239 维）→ 79 维有界残差
  → 策略：root=0；躯干 ×0.85；锁骨/上/前臂 ×0.20；
          手/脸/根=0；L0/L1 门控；3 帧平滑
  → 只重建 9 根上半身骨（spine/spine1/chest + 左右 clavicle/upperarm/forearm）
  → 用**未修改**的 M3 手/脸角度与 morph 重新装配
  → final.vmd
```

默认档不改变：

- 根（`root` 残差置零）；
- 腿/脚/趾（残差 layout 里没有腿因子，contact IK 输出原样保留）；
- 手指（30 条轨来自同一 `hand.npz`，逐帧不变）；
- morph（来自同一 `face.npz`，逐帧不变）。

### 4.2 回退层级

1. **窗口级**：整段 clip 的 jerk/脚滑/穿地门禁失败时，按 30 帧窗口定位，
   把失败窗口从修正中遮掉，并用更宽的平滑重建过渡；窗口记录在
   `feedback.json -> segments_fallback`，QC 警告 `segment fallback used`。
2. **整段级**：多轮后仍失败则 `whole_clip_fallback=true`，`final.vmd=before.vmd`，
   QC 警告 `whole clip fell back to feedback=off`。
3. **手/脸级**：若启用 full 档且手指/morph 步长退化，整段丢弃手/脸修正
   （`handface_fallback=true`）。

T5 默认档与合成 GT 默认档均为 **0 窗口回退、0 整段回退、0 手脸回退**。
实验 full 档在 T5 si 上真实触发了 4 个窗口回退 + 手/脸回退（见 §7），
说明回退链路在真实片段上可执行，而不是只写在代码里。

### 4.3 与 M3.5 的一致性

用同一 `m35_best.pt`、同一证据、同一策略在 T5 si 上复现
`outputs/m35/t5_final2/t5_si_fb.vmd`：53 轨、morph 一致，
逐骨四元数最大差 **0.0445°**（浮点/平滑实现差异），残差 mean |t| 9.0628
与 M3.5 报告逐值一致。说明 M4 的 application 层没有改变网络语义。

## 9. 已知上限与失败模式

1. **M3.5 次要代价仍在**：留出 test world **+1.65°**、position **+0.141%H**
   （侧机位为主）。M4 的 QC `secondary_ok=false`，并在 summary 的
   `secondary.heldout` 中原样列出；T5 无 GT，不能用 T5 的“修正幅度”
   冒充这个误差。
2. **手臂收益有限**：默认档 upperarm/forearm 只 −1.1/−1.8°（M3.5），
   合成片段上 upperarm 甚至 +0.09°（噪声级）；主收益来自躯干。
   这是已接受的手臂上限，不在本轮重开研究。
3. **T5 jerk 余量变小**：+4.82–4.94%，接近 5% 门禁（M3.5 是 +3.8–3.9%）；T1/T2 为 +3.72%/+3.90%，spikes 小幅增加（+12/+13，spike 不是门禁）。
   原因是每模型 GVHMR→adapter 的身体与 M3 的 si 身体不同；仍通过。
   若未来素材超过 5%，窗口回退会启用并显式记录，而不是静默放行。
4. **固定机位假设**：默认 `static_cam=true`；手持/运镜素材需要 GVHMR 的
   VO 分支，本轮未验收。
5. **自动取景偏紧**：1440×2560 portrait 下，提弗洛斯个别宽姿态帧的手臂
   会超出画面；before/after 相机一致，对比仍有效。需要“人物完整入画”
   时可增大 `render.margin`（render_synth.py 参数，当前未暴露到 CLI）。
6. **渲染耗时**：6 段 × 161 帧 × 1440×2560 × 12 samples 约 15 分钟
   （RTX 4060 Laptop）；Blender 偶发崩溃由重试覆盖。
7. **手/脸覆盖低**：T5 左 L0/L1 8.3%、右 1.7%、脸 L1 5.8%；
   默认不启用手/脸后馈；MANO/WiLoR 是后续升级项。
8. **无 MANO/真实配对数据**：网络仍只在合成域训练；真实素材的
   手臂/手/脸提升需要真实 GT 或 AMASS 级数据。
9. **长视频未分段**：M4 默认整段离线；M2.5 的流式组件没有接入本 CLI。
   长视频 OOM/超时属于后续工作。
10. **代码指纹会失效缓存**：改 `src/` 后第一次重跑会重做所有阶段
    （包括渲染）；这是为了防止旧缓存掩盖代码变化。只改文档不会。
