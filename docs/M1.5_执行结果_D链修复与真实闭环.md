## 2. P0：Blender 继承骨 bake（已完成）

### 2.1 根因（复核）

- 祀腿部 2926 顶点主权重在 `足D/ひざD/足首D`；VMD 只写 23 根 FK 骨。
- MMD 用 `付与親` 自动算继承骨；Blender 没有这个语义，MMD Tools 导入后 D 骨停在 rest。
- 旧 action 的 D 骨 fcurves 也被清掉，所以“直腿”不是权重问题，是 **Blender 侧缺继承求值**。
- 实测导入映射：VMD 帧 f → Blender 帧 **f+1**；PMX→Blender 位置 = `0.08·(x,z,y)`，
  旋转 = `S·R·Sᵀ`（S = 交换 Y/Z）；rest 头位置误差 2.4e-7。

### 2.2 实现

新增 `scripts/mmd_blender.py`（共享库）+ `scripts/bake_inherit_blender.py`（独立校验 CLI），
`scripts/render_synth.py` 默认启用（`--no-bake-inherit` 可关）。

算法（逐帧、逐继承骨）：

```
T_i = [ S·R_i·Sᵀ | 0.08·S·(p_i − R_i·h_i) ]          # PMX 求值器的形变矩阵
basis_i = M_i⁻¹ · T_parent⁻¹ · T_i · M_i             # M_i = Blender bone.matrix_local
```

- 只写 **继承骨** 的 local 旋转/位移；FK 骨完全来自 MMD Tools 导入（独立路径，用来交叉验证）。
- 写入时处理四元数半球连续、尺度检查、旧 fcurve 清理、逐帧 LINEAR 插值。
- 烘焙前后都做 **硬门禁**：`d_chain_vs_fk.ok` 与 `verify.ok` 任一失败，渲染脚本直接退出，不产出误导性视频。
- VMD 仍是 23 轨 + IK off；`tests/test_inherit_bake.py` 断言 MMD 资产里没有 D/捩1/肩C 轨。

### 4.2 误差归属：adapter 不是瓶颈

- **adapter 同模型往返**：M1 已测 18 个身体关节世界位置 max **1.6e-15 unit**、朝向 1e-5°；
  这次不改 adapter，复跑 `tests/test_adapter_roundtrip.py` 仍通过。
- **adapter 跨模型**：R2→提弗洛斯/洛茜 段方向偏差 1.1e-5°/5.7e-6°（M1 记录，未变）。
- **前馈闭环**：直接比较 GVHMR 的 canonical 姿态与 GT VMD 的 canonical 姿态（pelvis 相对，
  消掉全局朝向），mean **31.9°**、median **26.4°**、p90 **65.8°**；最差是手 **78°**、
  前臂 **50°**、上臂 **41°**、脚 **37-42°**、头 **35°**（`scripts/compare_canonical_sources.py` → `outputs/closed_loop/m1_5/front/canonical_source_diff.json`）。

结论：**误差主要来自 GVHMR 对非 SMPL-X 体型（长腿、外套、翅膀、尾巴）的单目拟合**；
adapter 精确。这和指导书预期一致（“这一步的误差主要来自 GVHMR/前馈”）。

### 4.3 三机位的“世界角”不可直接横比

`closed_loop` 的 `world_angle` 包含全局朝向。实测根骨世界角误差：

| view | 根骨世界角 mean | 根骨局部角 mean |
|---|---:|---:|
| front | 13.4° | 13.4° |
| three_quarter | 35.0° | 35.0° |
| side | **84.4°** | 84.4° |

相机绕角色转（frontal → 35° → 90°）时，GVHMR 从单目视频里恢复的“角色朝向”不跟真实世界 yaw 走：
越到侧面，世界角越被 yaw 误差放大（总世界角 104°）。
**局部角（≈40°）三机位一致**，才是姿态误差；世界位置/世界角只在正面机位可信。
这不是 bug，是单目全局朝向的不可观测性；写报告/门禁时必须分开。

### 4.4 修复前后对照（同一正面机位，旧 GT 视频 vs 新 GT 视频）

| GT 视频 | 局部角 | 世界角 | 位置 mean | 接触召回 | 滑动Δ | jerk× |
|---|---:|---:|---:|---:|---:|---:|
| 旧（直腿 bug） | 40.90 | 39.48 | 4.79 | 0.58 | **3.07** | 4.34 |
| 新（D 链修复） | 40.56 | 38.32 | 4.59 | 0.46 | **0.33** | 4.76 |

R2 本身膝角多在 135-141°，所以整体角度/位置变化不大；**脚底滑动改善 9 倍**
（3.07 → 0.33），说明“把 VMD 的真实膝弯渲染出来”对接触指标是有实质影响的。
接触召回从 0.58 降到 0.46：直腿渲染让脚更低、更容易被判为着地，但脚在滑——高召回不等于对。

### 4.5 已知问题（记录，不在 M1.5 修）

1. 手臂：上臂世界角 front ≈24-27°，但矢状面“前伸 vs 侧展”被 GVHMR 抬错；这是单目深度歧义 +
   非人形外形，需要更好的前馈或双侧/多视约束。
2. 全局 yaw：侧面机位不可观测（见 4.3）；跨机位融合/相机先验是 M2 的候选。
3. 接触：pred 接触召回 0.46（正面）说明预测脚常常“飘”；根高度/地面校准仍需逐帧约束。
4. jerk ×3.8-4.8：GVHMR 原始抖动，M2 选择性清理处理。
5. 上臂/前臂 local 角很大（85-92°/38-42°）主要是 **twist 分布差**（GT 用 捩/手捩，body-only
   导出把扭转放到上臂），不是位置/末端朝向错；看局部角时不要误读。

## 8. 下一步建议（不改 adapter/GVHMR 的前提下）

1. **门禁口径**：世界角/世界位置只在正面机位用；跨机位用局部角或“按根旋转对齐”的位置。
2. **M2 第一刀**：选择性清理（只修 flagged 帧）把 jerk ×4x 拉下来，别动舞蹈发力帧。
3. **前馈**：手臂前伸/内收是最大残差；先积累带 GT 的样本（合成三机位 + 真舞 T5/T1/T2），
   再决定是双侧/时序先验还是结构后馈——现在先写网络会缺少评估依据。
4. **接触**：接触召回 0.46 + 滑动，优先做逐帧脚锁/根高度；这比全局平滑更影响观感。
