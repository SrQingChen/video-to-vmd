### 2.2 触发

只在同时满足时启用：

1. 连续低置信洞 **≥6 帧（0.2 s）**；3–5 帧的随机短洞留给 v0 桥
   （0.4 s 释放会覆盖整个洞、没有锚定保持段；side random20 seed2 的 3 帧洞
   曾出现 0.49 的诊断漂移，虽然门禁仍过，但不锚定更稳）；
2. 洞前最后一帧是高置信观测（不是另一个洞；前 3 个高置信帧还必须连续）；
3. 某一侧在洞前 3 个高置信帧内被 `estimate_contact` 判为接触，**或**
   脚尖在接触带上沿 `+1% 身高`以内、三帧水平速度中位数 ≤0.15、单帧 ≤0.20
   （“悬空但稳定”的兜底；否则 front 左脚因自参考接触带低估而永远不触发）；
4. 三帧 toe XZ 相对中位数的最大偏离 ≤1% 身高。

摆动脚、洞内新落脚、`contact_hold` 之后的新接触都不会被锚定。
`anchor_orientation="v0"` 时只锚定 XZ；`anchor` 模式另外冻结洞前脚世界朝向和 Y。

### 2.3 锚点与目标

- `toe_anchor.xz` = 洞前 3 个高置信锚定帧的 toe 世界 XZ 中位数；
- `toe_anchor.y` = 三帧 toe Y 中位数（不压到地面）；
- `R_foot` = 洞前最后观测帧的脚世界朝向；`offset = toe_rest - foot_rest`；
- `ankle_target = toe_target - R_foot · offset`（`anchor` 模式），或
  `ankle_target = A_v0 + (toe_anchor.xz - toe_v0.xz)`（`v0` 模式，纯水平修正）；
- 目标只用洞前观测，绝不读洞内/GT；恢复观测只作为 v0 桥的终点。

### 2.4 2-bone IK 与信任域

- 链：hip → knee → ankle；保持当前膝盖弯曲平面（退化直腿用稳定平面兜底）；
- 每帧从当前 v0 姿态解到目标，膝弯曲变化 ≤15°、大腿方向变化 ≤25°、
  输出相邻帧踝位移 ≤2.5% 身高；
- 目标超出腿长或信任域时按权重二分降级（8 次采样 + 12 次二分），
  不做硬拉；`reach_limited_frames` 记录。

### 2.5 释放

- 洞末最后 0.4 s（12 帧 @30 fps）用 smoothstep 从锚定权重降到 `release_floor`；
- **`release_floor` 不是 0**：`budget` 模式按“洞末 toe 距锚点 ≤ slide_budget×0.95”
  反解最小权重。完全释放会把恢复观测的位移原样带回，正是 v0 的 0.17–0.35 脚滑；
  实测 front occ10 seed0 `full` 释放 drift 0.331，`budget` 0.026；
- `full` 保留为消融开关；两者都不改观测帧。

### 2.6 与 v0 的顺序

```
v0 fill（桥/rollout/0.25 混合/观测回写）
  → stance IK（仅低置信洞、仅支撑脚、仅 thigh/shin/foot）
  → 输出（观测帧已在 v0 回写，stance 不触碰）
```

根骨 XZ 沿用 v0 的接触阻尼，根骨 Y 完全不动；手臂/手指/morph/IK 段不碰。

## 3. 关键设计决策（与指导原文的差异）

### 3.1 默认 `anchor_orientation="v0"`，不是冻结脚朝向

指导原文要求“保持脚世界朝向 + 固定 toe Y”。实测在髋部抬高/腿接近伸直时，
锚定踝目标会超出腿长：side occ20 seed0 洞末 `|A_anchor-H| = 10.08`，
腿长 9.89，权重只能降到 0.33，脚滑 0.104、边界步长 15.4°；
front occ20 seed2 把悬空脚锚在 0.744（GT 带顶 0.733）上方，接触召回从 1.0
掉到 0.76。

默认改为 **只锚定 toe XZ，脚世界朝向和 Y 跟随 v0 桥**：

- 修正变成纯水平踝位移，腿的可达性与 v0 相同；
- 脚高不变，接触 recall/precision/height 不受影响；
- 脚朝向随 v0 平滑变化，边界步长更小（同例 6.7° vs 15.4°）；
- `anchor` 模式保留原文行为，供对照/复现，不作为默认。

### 3.2 `release_mode="budget"`，不是完全释放

完全释放到恢复观测 = 把“洞前脚位置 → 恢复脚位置”的位移放回脚上，
正是门禁测的脚滑。`budget` 只释放到洞末 toe 距锚点 ≤0.043（0.045×0.95），
残余位移在恢复帧以一次小边界步长出现；R2 实测边界步长 0.5–15.4°，
跳变门禁 0/0 通过。`full` 模式保留，用于证明“完全释放会重新引入 0.33 脚滑”。

### 3.3 悬空脚的兜底与 GT 拖脚

- `estimate_contact` 的接触带是自参考的（`min(toe_y)+0.02*height`），
  front 左脚比自己的带高 0.036 unit，但仍在 GT 带内；1% 身高 + 速度中位数的
  兜底把它纳入锚定，同时不改变脚高（`v0` 模式）。
- side occ30 有一个洞的 GT 脚尖在带内滑 0.355（拖脚），预测滑 0.357。
  预测器把它判为未支撑（速度 0.14–0.24 > 0.12），v0.1 不锚定它；
  这是“只对已检测到的支撑脚”的正确行为，也是唯一 0.053 > 0.05 的来源。

## 9. 已知上限

1. **R2 side occ30 脚滑 0.053**：GT 脚尖自身滑 0.355，预测 0.357 与 GT 吻合；
   三个 seed 的 GT 滑动均值 0.228/0.301/0.216，预测 0.073/0.043/0.043；
   预测器判为未支撑（速度 >0.12），按设计不锚定。要让这一行过，只能锚定
   一个 GT 正在拖动的脚，属于迎合度量、不是修正物理。bench 已新增
   `gt_slide_mean_units` 诊断（不入门禁）；建议后续把脚滑门禁改为
   “相对 GT 滑动的超额”或只统计 GT 真正静止的洞，而不是放宽 `hold+0.05`。
2. **front 长洞的 stream 缺口角**：front occ10/30 的 stream 比 hold 差
   +0.61/+0.34°，是 v0 的“长洞需要两端信息”上限；最终交付用 offline。
3. **锚定依赖检测**：洞前没有被判为支撑（或悬空超出 1% 身高 + 速度门）的脚
   不会被锚定；T5 的两个洞、side occ30 的拖脚都属于这一类。
4. **`anchor` 模式的腿长上限**：冻结脚朝向 + 固定 Y 时，髋部抬高会让锚定踝
   超出腿长，权重下降；需要更长的腿/移动根 XZ 才能解决，本轮不动根骨 Y。
5. **释放残余**：`budget` 在洞末保留 ≤0.043 的 toe 偏移，恢复帧有一次小步长；
   R2 实测边界步长 0.5–15.4°，跳变门禁 0；若产品更重视视觉平滑，可切 `full`
   释放，但会重新引入 0.17–0.35 脚滑。
6. R3 的接触指标（recall/precision）仍只作诊断；R3 GT 接触约 2%。
