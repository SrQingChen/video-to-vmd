## 2. 为什么 PMX ↔ SMPL-X 映射是这轮最硬的部分

### 2.1 适配器的重定向公式

`adapter.adapt` 对每个关节做：

```text
G_pmx(j) = Yaw · D_j · G_src(j) · D_j⁻¹
D_j = q_between(u_smplx(j), v_pmx(j))      # rest 方向补偿
D = I                                       # foot/toe（NO_SWING）
Yaw = 180°                                  # SMPL-X 源在本仓库的 stage yaw
```

把它反过来：

```text
G_src(j) = D_j⁻¹ · Yaw⁻¹ · G_pmx(j) · D_j
local_src(j) = G_src(parent)⁻¹ · G_src(j)
body_pose(j) = F(local_src(j))              # F: (x,y,z,w)->(-x,-y,z,w) 模型系反射
```

注意三点，任何一点错都会把“先验”算到另一个骨架上：

1. **不能省 Yaw**：`D_j` 逐关节不同，`D_p ≠ D_j`，所以 `Yaw` 不会在
   `inv(G_parent)G_j` 里自动消掉。漏掉 Yaw（或把 D 放在错误一侧）会留下
   15–77° 的臂/躯干误差。
2. **必须用 clip 的 betas**：`canonical_from_smplx` 的 rest joints 是**带形状**的
   SMPL-X。用零 betas 会在躯干/手臂留下 5–7° 的系统偏移；R2 的 betas 是
   `[-0.295, -1.986, -0.384, 0.491, -0.247, 0.629, -0.245, 1.119, -0.620, 0.326]`。
3. **脚要特殊处理**：`adapter.NO_SWING` 对 foot/toe 故意保持 `D=I`（SMPL-X 的
   脚段定义与 PMX 不同）。因此从 PMX 反推的脚 `body_pose` **不是**源的脚
   `body_pose`；VPoser 先验里必须把腿/脚冻结在源的 `body_pose` 上，否则脚的
   系统误差会污染编码器。

### 2.2 验证：R2 front 精确恢复 GVHMR `body_pose`

`src/vtv/vposer_body.py` 的 `body_pose_from_motion`，在 R2 front 上与
`outputs/gvhmr/R2fix_front/gvhmr_result.npz` 的 `smpl_params_global/body_pose` 比较：

| 组 | 平均测地误差 |
|---|---:|
| 上臂/前臂/手（6 关节） | **0.294°**（残差来自 cleanup 平滑） |
| 躯干（spine/spine1/chest/neck） | **0.000°** |
| 全部 21 关节 | 1.461°（腿/脚差异来自 contact IK 与 NO_SWING） |

D 角本身并不小：

| joint | D 角 |
|---|---:|
| spine1 | 27.28° |
| chest | 3.70° |
| clavicle_l | 54.22° |
| upperarm_l | 19.40° |
| forearm_l | 39.69° |
| upperarm_r | 26.57° |
| forearm_r | 34.53° |

这正是“不能直接把 PMX 的 local rotation 当 SMPL-X body_pose 喂给 VPoser”的证据。
`tests/test_vposer_prior.py` 用随机 `body_pose → canonical_from_smplx → adapt →
VMD → canonical_from_pmx → body_pose` 的闭环锁定到 **2e-6°**（脚除外），

## 3. VPoser v2 在本 clip 上的方向：先验与 GT 反相关

### 3.1 KL 诊断（`scripts/m24d_probe.py`）

| 量 | 预测 | GT |
|---|---:|---:|
| KL mean | **29.37** | **133.78** |
| KL median | 29.15 | 142.65 |
| 预测 KL < GT KL 的帧比例 | **1.0** | — |

把 GT 的某一组 `body_pose` 换进预测，再看 KL：

| 换入组 | KL mean |
|---|---:|
| GT 腿 | 33.31 |
| GT 躯干 | 28.94 |
| **GT 手臂** | **127.26** |
| GT 头 | 29.60 |

读法：

- **GT 的手臂是“低概率”的主因**。VPoser 在 AMASS 上训练，R2 的折叠手臂/夸张
  肩部组合不在它的高密度区；预测的“手臂张开”反而更接近人类均值。
- 一个把 GT 判得比预测更不可能的先验，**不可能把姿态指向 GT**。它能做的只有
  “把姿态拉向均值”。
- KL 的极小值不是“任意合理姿态”，而是 **decoder 在 z≈0 的均值姿态**。因此
  先验权重一大，姿态会整体塌向均值：w=0.1 时 KL 7.05、上/前臂 +28.14°、
  chest 38.77°。这不是调参问题，是能量本身的极小点。

## 4. Joint torso+arms BA：方法和扫描

### 4.1 方法

`src/vtv/ba3d.py` 扩展（M2.4c 的 BA + 本轮）：

- **优化变量**：`TORSO_ARM_CHAIN = spine/spine1/chest/neck + clavicle/upperarm/forearm`
  （**不含手**；手是不可直接观测的叶节点，单独报告）。根、腿、脚、IK 不动。
- **2D**：三机位肩/肘/腕/髋/膝/踝/neck，Huber 20px，手臂权重 2.0；每视角一个小根
  修正（不写出）。
- **VPoser 能量**：`canonical_to_body_pose_t(G)` 是**可微**的；
  `VPoserBodyPrior.energy` 用 `KL(q(z|x)||N(0,I))`。BA 只把 `vposer_joints`
  对应的 `body_pose` 维度当自由变量，其余维度**冻结在源 `body_pose`**（脚/腿在
  这里尤其重要）。VPoser 权重冻结，不训练。
- **先验**：局部增量 L2、时间一阶平滑、每视角根 L2、baseline-relative 碰撞 proxy
  （w=20，与 M2.4c 相同）。
- **写出**：`merge_pose_tracks` 只把优化链的 local 轨复制到 init VMD；根、腿、IK、
  手 local、morph 全部字节级不变。`verify_ba` 的 `non_arm_unchanged` 按优化链
  放行（torso+arms），手 local 仍严格检查；逐对预算/全局/时序/胶囊门禁不变。
- **GT 只读**：GT 只用于评分和 `max(baseline,GT)+0.02` 预算，不进入 loss。

### 4.3 为什么 `ta_w0` 的 3D 位置最好却不能接受

`ta_w0` 的肘/腕 3D mean 是 **4.42% 身高**（比 arms BA 的 6.29 更好），但：

- body-relative 上/前臂 **+1.89°**（变差）；
- chest world **27.78°**（比 11.16 差 16.6°）；
- 臂-躯干 0.523 全局尚可，但逐对预算失败。

这是 M2.4b/M2.4c 结论的第三次复现：**2D 位置/3D 位置可以在胸错的情况下变好，
body-relative 不会**。门禁必须以 body-relative 为主指标，3D 位置并列报告。

## 6. 为什么 10° 仍未达成

1. **VPoser 先验与 GT 反相关**：GT KL 133.78 vs 预测 29.37；GT 手臂换入后
   127.26。一个把 GT 判得更不可能的先验，方向不可能指向 GT；任何权重扫描
   都只会从“近 no-op”走向“拉向均值”。本轮把这一点量化到了能量层面。
2. **KL 的极小值是 decoder 均值姿态**：w=0.1 时 KL 7.05，但上/前臂 +28.14°、
   chest 38.77°。这不是“先验太弱/太强”的调参问题，是能量极小点不在 GT 附近。
3. **胸仍然没有可用观测**：freeze torso 时 chest 11.16° 不变；joint torso 时
   2D 把 chest 推到 27.78°（无先验）或 33–41°（有先验）。M2.4c §6.5 的
   “用胸补 2D”在本轮再次出现。VPoser 的躯干先验不是这个 clip 的躯干观测。
4. **左臂的 2D 地板**：左臂上/前臂 17.32/21.33，BA 后 17.33/20.56；三机位的
   左臂遮挡/骨点偏移让它几乎不动。右臂 −15.60/−8.35 无法把 4 骨均值拉到 −10°。
5. **手不可观测**：全 6 骨 −9.57° 是手 −16.34° 驱动的；手是叶节点，只有 wrist
   没有 palm/finger 方向。门禁必须把手分开，否则会用“前臂转手”冒充手臂改善。
6. **2D 信息量本身**：M2.4b 已量化单视 2D 方向 3–11°、三视三角化目标 15–25°；
   BA 把 2D 中位压到 33–39px（写出 62/63/52px），但关键点/骨点偏移和左臂遮挡
   仍是 floor。VPoser 没有补上这个信息缺口。

**诚实结论**：本轮不是“先验权重没调好”，而是**这个 clip 上的 VPoser v2 先验
方向与目标相反**；joint torso+arms BA 也再次证明“自由胸会把 2D 拟合成更差的
body-relative”。10° 需要的是**信息增益**，不是再调一个权重。
