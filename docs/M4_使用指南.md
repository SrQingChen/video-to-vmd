# M4 使用指南：一条命令从视频到三模型 VMD / 2K / QC

> M5 增补：长视频分段/合并、自动取景与发布候选见 [M5_使用指南](M5_使用指南.md)。

> 适用版本：M4（2026-10-28；M6 追加 v2）。M4 原文默认 = M3.5 保守档；
> **M6 后生产默认改为 `--feedback v2`**（躯干 0.85 / 手臂 0.30 / smooth 3；
> 手、脸、根关闭），M3.5 用 `--feedback default` 切回；full 手/脸用
> `--feedback v2_full`/`full`（opt-in）。质量优先：离线跑十几秒视频允许
> 十几分钟；RTF 不是门禁。

---

## 1. 它能做什么

```
输入一段单目视频（固定机位）
  → GVHMR（30 fps，static camera）
  → adapter（每个目标 PMX 各自一套）
  → 选择性清理（cleanup）
  → 接触/腿 IK（contact IK）
  → M3 手/脸证据（MediaPipe，所有模型共享）
  → 后馈（M6 默认 v2；M3.5 default 仍可用；只改躯干/锁骨/上臂/前臂）
  → VMD（23 身体 + 30 手指 + morph + IK off）
  → 2K before/after 固定机位渲染
  → QC（证书/稳定性/未变轨审计/次要代价/回退片段）
```

默认反馈**不会**改腿、脚、根、手、表情；VMD 固定 53 轨、4 个 IK off、
不写 D/helper、手指位移 0。

## 2. 环境要求

| 项 | 要求 |
|---|---|
| OS | Windows 10/11（当前所有证据都在 Windows 上产出；脚本依赖 `D:/blender`、`D:/ffmpeg` 这类路径，可改配置） |
| Python | 3.10.x（独立 venv；不要用系统 Python） |
| GPU | 已验证 RTX 4060 Laptop 8GB；GVHMR 首次跑 T5 242 帧约 1–2 分钟 |
| 磁盘 | C: 空间紧张时把 venv/pip/HF cache 放 E:（见 `scripts/bootstrap_env.sh`） |
| Blender | 5.x + MMD Tools 扩展；`configs/pipeline.json -> render.blender` |
| ffmpeg | 带 libx264；`configs/pipeline.json -> render.ffmpeg` |

非商业研究依赖：GVHMR + SMPL-X。商用需替换后端并取得授权，见 `MODEL_LICENSES.md`。

## 3. 从零安装

### 3.1 Python 环境

```bash
cd /e/zcodeAI项目/视频转VMD
bash scripts/bootstrap_env.sh          # 创建 .venv、torch 2.3.0+cu121、GVHMR 依赖
source .venv/Scripts/activate
export PYTHONPATH=src
```

M3 手/脸依赖（顺序重要；MediaPipe 会把 numpy 拉到 2.x、把 OpenCV 拉到 5.x）：

```bash
pip install mediapipe==1.1.1
pip uninstall -y opencv-contrib-python
pip install --force-reinstall --no-deps opencv-python==4.11.0.86
pip install "numpy==1.26.4"
```

### 3.2 不入库的素材/权重

这些**不在仓库里**，需要自备：

| 路径 | 内容 | 来源 |
|---|---|---|
| `third_party/GVHMR/inputs/checkpoints/gvhmr/gvhmr_siga24_release.ckpt` | GVHMR 权重 | 官方发布 |
| `body_models/smplx/SMPLX_*.npz` | SMPL-X v1.1 | MPI 官网（非商业） |
| `models/mediapipe/hand_landmarker.task` | MediaPipe 手 | `storage.googleapis.com/mediapipe-models/...` |
| `models/mediapipe/face_landmarker.task` | MediaPipe 脸 | 同上 |
| `outputs/m35/net/m35_best.pt` | M3.5 后馈网络（2.10M） | 本项目训练产物，见 `docs/M3.5_执行结果_数据引擎与后馈网络.md` |
| 三套 PMX + 三人 `.blend` | 祀 / 洛茜 / 提弗洛斯 | 用户自有，不入库 |
| `profiles/{si,luoxi,tiflos}.json` | 每模型 rest/骨名/morph 映射 | 由 PMX 生成（`scripts/make_profiles.py`） |

`configs/models.json` 里的 PMX/blend 路径必须与本机一致；`configs/pipeline.json`
里的 `render.blend` 指向包含三人的场景（本项目证据使用
`三人_王牌竞速_20261024.blend`）。

### 3.3 预检

```bash
python scripts/check_env.py --models si,luoxi,tiflos
```

全部 `OK` 再继续；`WARN` 只影响可选功能（例如不用反馈时 ckpt 可缺）。

## 4. 一条命令

### 4.1 T5 三模型（默认档 + 2K before/after + QC）

```bash
python scripts/run_vtv.py \
  --video testdata/T5_高速舞蹈_001/001.mp4 \
  --out outputs/m4/t5 \
  --models si,luoxi,tiflos \
  --feedback default \
  --render
```

输出：

```
outputs/m4/t5/
  manifest.json                 # 每阶段输入哈希/配置/输出/耗时
  video/gvhmr/                  # 30fps 视频、npz、ViTPose、meta
  evidence/hand, evidence/face  # MediaPipe 证据（三模型共享）
  models/si/                    # adapter/clean/ik/before/after/final + 证书
  models/luoxi/ models/tiflos/
  models/*/render/before, render/after
    <model>_<tag>_70-230.mp4    # 161 帧、1440x2560、12 samples
    frames/ stills/ render.json # 渲染证书：D 链/verify/scale
  models/*/qc.json              # 每模型 QC
  qc/summary.json, summary.md   # 汇总与门禁
  logs/                         # 每个子步骤的原始日志
```

### 4.2 只跑数值、不渲染（快）

```bash
python scripts/run_vtv.py --video testdata/T5_高速舞蹈_001/001.mp4 \
  --out outputs/m4/t5 --models si,luoxi,tiflos --feedback default --no-render
```

### 4.3 对照档

```bash
# 纯 M3 输出（feedback off），用于 before/after 对照
python scripts/run_vtv.py ... --feedback off --out outputs/m4/t5_off

# 全量档仅作实验：M3.5 无回退时 T5 手指/morph 步长失败；
# M4 会回退部分窗口/手脸（见执行结果 §7），仍不推荐
python scripts/run_vtv.py ... --feedback full --out outputs/m4/t5_full
```

### 4.4 慢动作源（T1/T2）

`--slow-factor` 与 adapter 的采样规则一致（输出仍 242 帧、30 fps）：

```bash
python scripts/run_vtv.py --video testdata/T1_.../001.mp4 --slow-factor 0.25 ...
python scripts/run_vtv.py --video testdata/T2_.../001.mp4 --slow-factor 0.5 ...
```

### 4.5 合成片段带 GT 的 QC

```bash
python scripts/run_vtv.py \
  --video outputs/m35/render/R3_si_front/R3_si_front.mp4 \
  --out outputs/m4/r3_si --models si --no-render \
  --gt si=outputs/m35/gt/R3/si.vmd
```

有 GT 时 QC 会计算 body-relative main、chest/upperarm/forearm、
接触/穿透/时序，以及 world/position 的**真实误差增量**。

## 5. QC 怎么读

`qc/summary.md` 是给人看的，`qc/summary.json` 是机器可读的；每模型
`models/<m>/qc.json` 是完整证据。

### 5.1 两层门禁（必须分开读）

| 层 | 内容 | 是否阻塞 |
|---|---|---|
| **task gate** | VMD 证书（53 轨/30 指/IK off/无 D/helper/手指位移 0）、GT-free jerk/脚滑/穿地/手指步长/morph 步长、根/腿/手/脸未变审计、有 GT 时的 body-relative + 接触/时序 | 是 |
| **secondary** | 绝对 world-angle、3D 位置误差增量 | 否，但**必须报告**；超过 +2° / +0.2%H 会显式警告 |

T5 没有 GT，所以 task gate 的 body-relative 部分来自 M3.5 整段留出评测
（`outputs/m35/eval/report_default.json`，9 段 4,860 帧，主指标
37.55°→27.38°，task_gate=true）。T5 QC 会把这份参考和它的
world +1.65° / position +0.141%H 次要代价一起写进 `secondary.heldout`，
不会把 T5 的“无 GT”伪装成“次要代价为 0”。

注意：`secondary.heldout` 对应的是 **default 档**。`--feedback off` 的
`applied=false`，实际没有这份代价；`--feedback full` 也不是该参考的配置。
看 `feedback.applied` / `secondary.available` / `gt` 区分。

### 5.2 回退

- 默认档只改上半身；腿/脚/根/手/脸在结构上不会变，QC 会逐轨验证。
- 如果整段 clip 的 jerk/脚滑/穿地/**arm-torso 胶囊 proxy** 门禁失败，pipeline 会把
  失败的 30 帧窗口从修正里遮掉并重新平滑；`feedback.json -> segments_fallback`
  记录窗口，QC `warnings` 里出现 `segment fallback used`。arm-torso 使用与 QC
  task gate 相同的 +0.02 预算（M5 起）。
- 如果仍然失败，整段回退到 M3 输出（`whole_clip_fallback=true`），
  `final.vmd = before.vmd`，并在 QC 里标记。
- 手/脸修正若造成手指/morph 步长退化，会被整段丢弃
  （`handface_fallback=true`）。

## 6. 缓存、断点、重跑

`manifest.json` 为每个阶段记录：输入文件 sha256、阶段配置、代码指纹
（`pipeline_code`）、输出哈希、耗时。满足以下条件才复用：
状态 ok、输入哈希一致、配置一致、代码指纹一致、输出仍存在。

```bash
# 断点：直接重跑同一条命令；已完成的阶段打印 cached
python scripts/run_vtv.py --video ... --out outputs/m4/t5 ...

# 只重跑某个阶段（下游因输入变化会自动重跑）
python scripts/run_vtv.py ... --force feedback

# 只跑指定阶段（用于补 QC，不重跑上游）
python scripts/run_vtv.py ... --stage qc --force qc

# 忽略 manifest，全部重跑
python scripts/run_vtv.py ... --no-resume

# 预热上游：把已有 GVHMR/手/脸缓存接入新 run（不同 run 目录）
python scripts/run_vtv.py --video ... --out outputs/m4/t5_new \
  --seed gvhmr=outputs/m4/t5/video/gvhmr \
  --seed hands=outputs/m4/t5/evidence/hand \
  --seed face=outputs/m4/t5/evidence/face
```

注意：

- `--seed` 会清空目标缓存目录后复制；不能指向同一 run 内部（有路径重叠保护）。
- 改了 `src/` 或关键 `scripts/` 会自动让所有阶段失效；这是有意的，避免拿旧缓存
  掩盖代码变化。
- 只改文档/README 不会让缓存失效。

### 6.1 失败定位

- 失败阶段写入 `manifest.json -> stages.<key>`（`status=failed`, `error`,
  `traceback`），并在 `logs/<key>.log` 保留子进程输出。
- 默认遇到失败立即停止；`--keep-going` 会继续其他模型并在 summary 的
  `errors` 里列出。
- 渲染失败会重试（`render.retries`，默认 2）；帧数不完整也会失败，不会静默。

## 7. 配置（configs/pipeline.json）

| 键 | 说明 |
|---|---|
| `models` | 默认模型列表（也可 `--models` 覆盖） |
| `slow_factor` | 源视频慢动作倍率；1.0 正常，0.5 T2，0.25 T1 |
| `gvhmr.static_cam` | 固定机位（默认 true）；镜头运动视频需要 VO，当前证据只覆盖固定机位 |
| `hand` / `face` | MediaPipe 检测参数（input_size/conf/overlays） |
| `feedback.mode` | `v2`（M6 默认）/ `v2_full` / `default`（M3.5）/ `off` / `full` |
| `feedback.ckpt` | M3.5 checkpoint 路径 |
| `feedback.ckpt_v2` | M6 v2 checkpoint 路径 |
| `feedback.modes` | 每档的 torso/arm gain、smooth、手/脸/根开关 |
| `feedback.overrides` | 临时覆盖（例如只改 `arm_gain`，用于消融） |
| `feedback.fallback` | M3.5/M4 的窗口长度、最大轮数、边缘 ramp |
| `feedback.fallback_v2` | v2 专用（proxy 关闭、jerk 5%、脚滑/穿地/整段回退） |
| `render` | blender/ffmpeg、分辨率、帧段、samples、stills、重试 |
| `render.blend` | 三人场景；为空时用 `configs/models.json` 的 per-model blend |
| `qc.heldout_reference` | M3.5 留出报告路径（T5 无 GT 时的参考） |

**默认档不要改**：`torso_gain=0.85`、`arm_gain=0.20`、`smooth=3`，
`apply_root/apply_hands/apply_face=false`。全量档在 M3.5 会失败；M4 的回退链路会回退部分窗口/手脸，但它仍是实验档，不推荐。

## 8. 已知问题

1. **固定机位假设**：默认 `static_cam=true`。手持/运镜素材需要 `run_gvhmr.py`
   的 VO 分支，当前未在 M4 验收；不要直接套。
2. **T5 手臂上限**：手臂世界角仍有已知误差（M2.4c 最优 body-relative
   上/前臂 −6.18°，未达 10°）。默认后馈对手臂只有 0.2 gain，收益小；
   这是已接受的上限，不要在本轮重开手臂研究。
3. **手/脸覆盖低**：T5 左 L0/L1 8.3%、右 1.7%、脸 L1 5.8%；默认不启用
   手/脸后馈。MANO/WiLoR 是后续质量升级项。
4. **T5 次要代价**：M3.5 留出集 world +1.65°、position +0.141%H（侧机位为主）。
   QC 会持续警告；这是 task gate 之外的已知 trade-off。
5. **渲染耗时**：三模型 × before/after × 161 帧 × 1440×2560 × 12 samples
   约十几分钟（RTX 4060 Laptop）；Blender 偶发崩溃由重试覆盖。
6. **GVHMR 8GB 显存**：T5 242 帧可跑；更长视频可能 OOM。长视频分段/流式
   属于后续工作（M2.5 已有流式组件，但 M4 默认离线整段）。
7. **profiles 不入库**：从零安装必须先用 `scripts/make_profiles.py` 生成
   `profiles/*.json`，否则 `check_env.py` 会报缺失。
8. **中文路径**：MediaPipe C 层不能直接打开含中文的绝对路径；脚本内部已用
   `os.path.relpath`，但请从仓库根目录运行。
9. **不要手改 `final.vmd` 后指望缓存自动更新**：QC/渲染会把
   `final.vmd` 当输入；手改后重跑 QC 即可（渲染阶段会因哈希变化自动重跑；
   若用 `--stage` 过滤则需显式包含 `qc`/`render_after`）。

## 9. 复现 M4 证据

```bash
# 环境
python scripts/check_env.py --models si,luoxi,tiflos

# T5 三模型：一条命令，2K before/after + QC
python scripts/run_vtv.py --video testdata/T5_高速舞蹈_001/001.mp4 \
  --out outputs/m4/t5 --models si,luoxi,tiflos --feedback default --render

# 合成 GT 集成检查（验证 body-relative 与 M3.5 一致）
python scripts/run_vtv.py \
  --video outputs/m35/render/R3_si_front/R3_si_front.mp4 \
  --out outputs/m4/r3_si --models si --no-render \
  --gt si=outputs/m35/gt/R3/si.vmd

# 缓存/断点/强制重跑
python scripts/run_vtv.py ... --out outputs/m4/t5 ...            # 全 cached
python scripts/run_vtv.py ... --out outputs/m4/t5 --force feedback --no-render
python scripts/qc_report.py --run outputs/m4/t5                  # 重建 summary

# 单测
python tests/test_feedback_apply.py
python tests/test_pipeline.py
```
