> 日期：2026-10-27。工作目录：`E:\zcodeAI项目\视频转VMD`。
> 前置：M0–M2.5 v0.1 已完成；身体 VMD 23 轨 + 4 IK off；默认 `cleanup+ik`。
> 本轮**只做可行性审计**，不集成、不改身体、不训练网络。
> 质量优先，RTF 不作门禁；**没有 commit**。

## 1. 结论先行

| 项 | 结果 |
|---|---|

| 手指角逐帧抖动（校验帧，3D） | 左 p50 **4.25°**、p95 **26.67°**；右 p50 **18.93°**、p95 **63.35°** |
| MediaPipe VIDEO 跟踪模式 | 左 32.6%、右 25.6%；p50 6.4°/12.1°，p95 56.0°/89.3°；最长段 7/6 帧——连续性略好，仍不足以做连续 L0 |

| MediaPipe Face Landmarker（T5 全 242 帧，头部裁剪 5 尺度） | 检出 **80/242（33.1%）**；blendshape 逐帧步长 p50 **0.031**、p95 **0.601**、max **0.995**；动漫脸网格常整体偏移（见 §5） |
| 运行耗时（CPU） | 手 13.4 ms/裁剪（1452 次）；脸 6.9 ms/裁剪（627 次） |
| WiLoR / HaMeR | **不可用**：本机没有 MANO 权重；MANO 官方站点需要注册/接受许可；没有使用非官方镜像。见 §4 |
| 决策 | **本轮用 MediaPipe 打通 L0–L3 + VMD 手指/morph 轨**；只对“几何可信 + 段内稳定”的短片段给 L0/L1，其余 L2/L3 fallback；架构保留 MANO 手部专家替换点 |

**一句话**：T5 的手只有 ~23–50 px 掌宽，且大量被大袖子/头发遮挡；MediaPipe 能偶尔认出“这是一只手”，
但单帧/短段的可信率只有 4–7%，角度抖动 20–60°/帧。**它足以验证 L0–L3 与 VMD 手指/morph 管线，
不足以提供连续高保真手指动作**；没有 MANO 权重时这是正确边界，不应为了“有输出”硬写低置信检测。

## 2. 审计方法

### 2.1 数据

- 视频：`outputs/gvhmr/T5/0_input_video.mp4`（30 fps、242 帧、1080×1920；与 VMD 帧一一对应）。
- 身体 2D：GVHMR 预处理里的 ViTPose COCO-17（`outputs/gvhmr/T5/preprocess/vitpose.pt`）。
- 审计覆盖**整段 242 帧**（指导要求 30–50 帧；全段更便宜、也能看连续性），左右手分别统计。

### 2.2 手部裁剪

每帧、每侧用身体手腕/肘生成 3 个候选框：

```
palm_px   = 0.34 × |wrist - elbow|          # 掌长（wrist→middle MCP）
center    = wrist + 0.35/0.60/0.20 × palm_px × forearm_dir
half      = 1.10/1.50/2.05 × palm_px
输入       = 裁剪切出后立方插值到 640×640
```

只保留 `(几何是否通过, -失败项数, score)` 最好的候选。左右手**只用身体侧别**
（COCO 9/10）分配，MediaPipe 的 handedness 只记录、不用于分配（动漫手/镜像裁剪下不可靠）。

### 2.3 几何校验（逐帧）

| 检查 | 范围 | 作用 |
|---|---|---|
| 掌宽/掌长 | 0.30–2.2 | 拒绝退化/错误的“手” |
| 四指链长/掌长 | 0.40–2.2 | 拒绝部分手指/袖子 |
| 四指链长极差 | ≤1.0 | 拒绝“五根手指长度全乱” |
| 拇指链长、拇指根位置 | 0.35–3.2、0.2–2.5 | 拒绝非手物体 |
| 3D 手掌尺度 / 深度跨度 | 0.04–0.22 m、0.005–0.30 m | 拒绝退化的 world landmarks |
| 检测腕 vs 身体腕 | ≤3 掌长 | 拒绝跑到别处的手 |
| 掌长 vs 身体预期 | 0.35–3.0 | 宽松（2D 前臂会透视缩短） |

### 2.4 时序校验（本次审计新增，M3 实现沿用）

- 段内 **3D/2D 屈曲角一致性**：`median |3D − 1.5×2D|`（mcp/pip/ip 关节）≤35°；
- 段内 **掌长变异系数** ≤0.22；
- 段内 **角度步长 p90** ≤30°（L0）/≤50°（L1）；
- 孤立帧、<3 帧的段不进 L0/L1。

这些门槛是在审计中逐步加上的：**只看 MediaPipe score 会把袖子/头发当成手**
（例如 f120R，score 0.97、几何上像一只手，但画面里只有袖口与头发）。

### 2.5 VIDEO 跟踪与分辨率对照

- VIDEO 模式：每侧独立 detector，裁剪中心用 5 帧中值平滑的身体手腕；时间戳单调。
- 分辨率：320/512/640 输入，在 61 个抽查帧上比较“几何可信帧-侧”比例。

## 3. 手部结果

### 3.1 全段检出/校验

| 侧 | 原始检出 | 原始率 | 校验通过 | 校验率 | score 中位（校验） | 掌长/预期 中位 | 腕误差/掌长 中位 | world 掌尺 中位 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 左 | 104/242 | 43.0% | 18 | **7.4%** | 0.93 | 0.64 | 1.41 | 0.087 m |
| 右 | 56/242 | 23.1% | 11 | **4.5%** | 0.88 | 0.61 | 0.82 | 0.079 m |

- 最长连续校验段：左 **3 帧**（113–115），右 **4 帧**（37–40）。
- 校验帧 3D 角度步长：左 p50 4.25° / p95 26.67° / max 46.57°；
  右 p50 18.93° / p95 63.35° / max 81.63°。
- 2D 角度步长更大（左 p95 45.1°、右 74.6°），说明**2D 角度的抖动比 3D 更严重**；
  M3 的 L1 因此必须加 2D→3D 增益 + 阻尼 + 段级门控。

### 3.2 VIDEO 模式

| 侧 | 检出率 | 角度步长 p50 | p95 | 最长段 |
|---|---:|---:|---:|---:|
| 左 | 32.6% | 6.4° | 56.0° | 7 帧 |
| 右 | 25.6% | 12.1° | 89.3° | 6 帧 |

VIDEO 模式的中位抖动略好，但 p95 仍有 56–89°，且最长段只有 6–7 帧；
IMAGE 模式 + 段级门控更可控（不依赖跟踪状态），M3 采用 IMAGE。

### 3.3 分辨率

抽查 61 帧 × 2 侧 × 3 缩放：320/512/640 输入的几何可信比例为 **23.0%/23.0%/26.2%**。
640 有约 3 个百分点的收益，M3 默认 `--input-size 640`。

### 3.4 失败模式

1. **大袖子/头发遮挡**：手在画面里只剩袖口或手套边缘；MediaPipe 仍可能给 0.9+ 的置信度。
2. **手掌太小**：T5 全 242 帧的掌长中位约 25–40 px（1080p），上采样不能补回信息。
3. **左右手混淆**：手在脸/胸前交叉时，裁剪可能框到另一只手；MediaPipe 的 handedness 在
   动漫手上左右标签混用（左裁剪 79 次 Right / 60 次 Left）。
4. **单帧/短段尖峰**：校验后的段仍有 20–60°/帧的角度跳变，直接写 VMD 会抽搐。

## 4. WiLoR / HaMeR / MANO 可得性

| 项 | 结果 |
|---|---|
| 本机 MANO 权重 | **无**（`models/`、`body_models/` 只有 DWPose/SAM2/DAv2/VPoser/SMPL/SMPL-X；`find -iname '*mano*'` 为空） |
| WiLoR / HaMeR 代码/权重 | 本机没有；官方权重依赖 MANO |
| MANO 官方获取 | `mano.is.tue.mpg.de` 需要注册并接受许可；未自动化、未用非官方镜像 |
| 结论 | 按指导“没有 MANO 权重就用 MediaPipe 打通 L0–L3，不阻塞” |

**替换点**：`run_hand.py` 的检测段（crop → landmarks/world landmarks → `hand_plausibility`）
是唯一依赖手部专家的地方；`src/vtv/hands.py` 的 PMX rig、角度→局部四元数、L0–L3、平滑
与专家无关。后续拿到 MANO/WiLoR 时只需把检测段换成 MANO 21 关节，角度提取与写出不变。

## 5. 脸部结果

| 项 | 结果 |
|---|---|
| Face Landmarker 检出 | **80/242（33.1%）**（头部裁剪 5 尺度，512 输入） |
| 检出时脸框宽度中位 | 145.6 px（1080p） |
| blendshape 逐帧步长 | p50 0.031、p95 0.601、max 0.995（52 维汇总） |
| 耗时 | 6.9 ms/裁剪（627 次） |

**网格偏移**：动漫脸经常被 MediaPipe 的 478 点网格整体放到额头/头发上（证据
`outputs/m3/face_f140.png`：网格覆盖刘海与额头，眼睛位置错误；`outputs/m3/face_f200.png`
覆盖较准，但眼/嘴仍偏移）。因此 blendshape 在多数帧不可信；M3 的 L0 条件设得很严，
实际 T5 没有 L0，只有 14 帧 L1（EAR/MAR 几何）通过段级稳定门控。

## 6. 决策（进入 M3 实现）

1. **主方案 MediaPipe**：手用 Hand Landmarker（21 点 2D + world 3D），脸用 Face Landmarker
   （478 点 + 52 blendshape）；不下载非官方 MANO。
2. **只信任短段**：L0/L1 必须通过几何 + 3D/2D 一致性 + 掌长稳定 + 段级步长门控；
   孤立帧/2 帧段一律 fallback。
3. **fallback 是主路径**：T5 的 L0/L1 只覆盖 1.7–8.3% 的帧；其余 L2（轻微屈曲）或 L3（中性），
   由时序平滑与速率限幅保证不抽搐。
4. **手指只写局部旋转**：不写位移、不写 D/helper；左右手由身体腕消歧。
5. **表情只写 profile 实际存在的 morph**：L0 blendshape→语义→每模型别名；L1 只用眼/嘴几何；
   L2/L3 中性 + 程序化眨眼；动漫嘴部几何默认不驱动口型（`l1_mouth=False`），避免“半张嘴抽动”。
6. **架构保留 MANO 替换点**：见 §4。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 低置信检测被当成真手，渲染出错误手势 | 段级门控 + 掌长 CV + 3D/2D 一致性 + 左右腕消歧；短段直接 fallback |
| 2D 角度被透视压缩 | L1 增益从 L0 帧拟合（本次 1.5 上限），再乘 0.85 阻尼 |
| 动漫脸 blendshape 乱跳 | 全局 EAR 基线；单侧闭合→软双侧眨眼；blink 长保持判为不可靠并替换为程序化 |
| 手部专家缺失导致覆盖率低 | 接受为 T5 的已知上限；MANO/WiLoR 到位后替换检测段即可 |
| Blender 不导入 VMD morph | 导入时同时选中带 shape key 的 mesh，并清掉 .blend 自带的 idle face action（M3 实现已验证） |

## 8. 复现

```bash
cd /e/zcodeAI项目/视频转VMD
source .venv/Scripts/activate
export PYTHONPATH=src

# M3.0 全段审计（手 + 脸）
python scripts/m30_handface_audit.py \
  --video outputs/gvhmr/T5/0_input_video.mp4 \
  --kp outputs/gvhmr/T5/preprocess/vitpose.pt \
  --out outputs/m3/audit
```

环境：MediaPipe 1.1.1（`pip install mediapipe==1.1.1`；**装完要把 numpy 降回 <2**，
否则 torch 2.3.0 会报 `_ARRAY_API not found`；OpenCV 保 4.11.0.86）。
模型：`models/mediapipe/hand_landmarker.task`、`face_landmarker.task`（Apache-2.0，
从 `storage.googleapis.com/mediapipe-models/.../latest/` 下载，不入 git）。
