## 2. 协议

### 2.1 数据与相机

- **R2 合成三机位**：`outputs/synth/si_R2_fixed/{front,three_quarter,side}/`
  的 250 帧 1080×1920；Blender 相机实际 FOV **39.6°**（lens 50mm /
  sensor 36mm）；GT 为 `outputs/gt/si_R2_safe.vmd`。
- **T5**：`outputs/gvhmr/T5/0_input_video.mp4` 242 帧 1080×1920；GVHMR
  `K_fullimg` 换算的输入 FOV **47.1°**；T5 无 GT，只做时序/穿透/渲染。
- 输入按 Multi-HMR 的 `ImageOps.contain + pad` 到 896×896，K 用实际 FOV
  缩放，principal point 取 896/2。
- 检测阈值：`det_thresh=0.3` 时 front 7/250、side 16/250 漏检；最终用
  **0.1**，三机位/T5 全部有效。`0.1` 下 front/3-4/side 有 10/7/7 帧 >1 人，
  T5 17/242 帧 >1 人；脚本取 detector score 最高者。

### 2.2 接入

```text
Multi-HMR per-frame SMPL-X body_pose
  → scripts/run_adapter.py --model si --stage-yaw 180
  → candidate.vmd（23 轨，root/腿来自候选）
  → merge_pose_tracks(baseline, candidate, joints=clavicle/upperarm/forearm)
  → 评分
```

- **只合并 `clavicle_l/r`、`upperarm_l/r`、`forearm_l/r`**；手 local、根、
  腿、脚、IK、morph 全部保留基线（与 M2.4c arms BA 的“手单独报告”一致）。
- **torso_arms 变体**：额外合并 `spine/spine1/chest/neck`，用于检验候选胸
  观测；手臂数字不变（28.09/29.60/42.14），胸 body-relative 改善。
- **三视融合**：对同一 arm local 在三个视角取四元数均值（先对齐半球），
  再合并；这是“现成模型 + 最朴素融合”，不是重新训练。
- **平滑变体**：候选 arm local 做 5 帧中值（半球对齐），再合并；用于判断
  时序回退是否只是单帧尖峰。
- GT 只读；没有进入任何选择/优化。

### 2.3 指标

- `body_relative_errors`：上臂/前臂方向在**各自 chest 系**下的角度误差；
  4 骨均值 = 主指标（M2.4c/M2.4d 同口径）。
- `chest_rel`：chest 相对 pelvis 的旋转测地误差；`chest_swing`：chest→neck
  方向在 pelvis 系下的角度误差（本轮补充）。
- 肘/腕 3D：关节位置相对 pelvis，旋转到 pelvis 系，除以 PMX bbox 高度；
  **不用绝对世界位置**（候选 root 与 GT 不同）。
- 穿透：PMX rigid-body 胶囊；全局 arm-torso/arm-arm max；逐对预算
  `after <= max(baseline, GT)+0.02`；strict 逐对只作诊断。
- 时序：四段 arm 方向的逐帧最大/p99 角度；jerk：pelvis-frame 位置的
  三阶差分 RMS 比。
- 手单独报告，不计入主指标。

## 5. 为什么负

1. **域差**：Multi-HMR 训练于真实人（BEDLAM/AGORA/CUFFS/UBody），R2/T5 都是
   动漫/三渲二角色，手/袖/尾/裙摆会误导检测与深度。检测在 0.3 阈值下漏
   7–16/250 帧就是信号；0.1 能检出，但姿态仍不稳。
2. **逐帧独立**：没有视频时序先验，左右臂在深度歧义下翻转；100–150° 的
   单帧/双帧尖峰是 body_pose 本身，不是适配器。
3. **手臂相对自己的胸也更差**：full body 的 upper/fore 与 merged arms 都是
   28.09/29.60/42.14；不是“胸错导致手臂看起来错”。torso_arms 也修不了。
4. **穿透**：手臂上/前臂被推到 head/neck/chest/对侧臂，逐对预算大面积失败；
   5 帧中值只能降 p99，不能消除 max 和穿透。
5. **平滑后的上限**：三视融合 + 5 帧中值 26.48°，仍比 GVHMR 基线 24.07 差
   2.41°，比 M2.4c 17.89 差 8.59°；**不存在“再调一下就到 10°”的空间**。
6. **唯一正信号是躯干**：chest body-relative 11.34° vs 17.01°、chest swing
   10.70° vs 16.28°。但手臂是主门禁，且 chest world 在 3/4/side 变差；
   本轮不把它作为新 backend 继续投入。若未来做“躯干观测”研究，可以把它
   当作一个外部观测源，但不应再占用手臂预算。

## 6. 决策与下一步

- **不集成 Multi-HMR**；不作为 backend、初始化或 opt-in 阶段。
- **接受当前手臂上限**：默认仍 `cleanup+ik`；M2.4c arms BA（17.89°）仍是
  opt-in/多视上限，不默认开。
- 按 M2.4d 选项 C 推进：**M2.5 流式/缺口补全 → M3 手/表情 → M4 产线/开源**。
- 不再调无条件 VPoser/2D/world/roll/目标约束/铰链；不再为手臂训后馈网络。
- 可复用资产：
  - `scripts/mh_infer.py`：任意官方 SMPL-X 单帧模型的推理→GVHMR 兼容 npz；
  - `scripts/bench_external_3d.py`：任意候选 VMD 的 body-relative/3D/穿透/
    时序/jerk 评测 + 三视融合 + 平滑 + 逐对预算；
  - `run_adapter.py` 的 stage yaw 180 路径与 `merge_pose_tracks` 的
    “只合并手臂”安全边界。
- 如果以后要补 SAM 3D Body：先申请 HF 访问并解决 MHR→SMPL-X；如果显存
  升级到 16GB+，再评估 SMPLest-X/WHAC。不要在 8GB 上重复本轮。
