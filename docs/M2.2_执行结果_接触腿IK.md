`scripts/diag_contact.py`（GT 只用于**评测**，不进求解器）。前视数据：

| 右趾高 误差 mean/std | — | +0.206 / 0.129 | 右脚接近，偏置较小 |

| 大腿/小腿骨长 | 4.885 / 5.001 | 4.885 / 5.001 | 骨长一致 → 不是缩放 |

关键判断（决定了方法）：

1. **在 root-aligned 空间里腿几乎是准的**：前视左踝相对骨盆只差 +0.008 unit，
   左膝屈曲多 9°。所以“脚高错”不是脚的问题，是骨盆高度 + 膝屈曲的组合。
2. **常数偏置模型成立**：误差 std 只有 mean 的 27%，而逐帧“把峰值压到带内”
   （`mode=band`）会把误差信号的高频部分复制到膝盖上 —— 实测 jerk 更差、
   脚高 MAE 反而只到 1.41%。
3. **可达性有限**：左腿从 30° 伸到 15° 只能把脚踝下移约 0.19 unit（实测每帧
   trust cap 的中位数 0.232、p5 0.191），而 hover 是 0.370；剩下的 0.14
   不是腿长能补的，是骨盆高度。
4. 因此**不动根骨 Y**（开发指导 §2.5），把 0.23 的腿伸展余量用满，其余如实报告。

## 3. 算法

`src/vtv/contact_ik.py` + `scripts/solve_contact_ik.py`。

1. **地面估计**：两只 toe 各自做 3 帧滑动平均后取最低值，再取两者的 min（`max(0, ·)`，
   与评测的 y=0 地板一致）。单帧毛刺不会移动整段。
2. **接触概率** `p_contact`：
   - 高度带：`h = y - floor`，`enter = 1.5×band`、`exit = 2.0×band`（迟滞），
     `band = 0.02×height`（与 closed-loop 的 contact margin 相同）；
   - **垂直**速度门 `<0.10 unit/frame`（踩地的脚不会上下快移）；
   - 可选 2D 证据：ViTPose 踝关键点置信度（0.2→0.5 线性），`--kp2d`；
   - 空洞 ≤2 帧桥接、孤岛 <3 帧丢弃；
   - **水平速度刻意不进 `p_contact`**：在地面上拖动的脚仍然是接触，
     水平速度只用于 XZ 锁定（那是 cleanup 的 `foot_lock` 的职责）。
3. **常数偏置**（`mode=bias`，默认）：`hover_side = min_y_side - (floor + target_frac·band)`，
   `target_frac=0` 即“把最低点放回地面”。
   - `hover < 0.15·band` → 已经是踩地的，**不动**（侧面两脚都落在这一条）；
   - `hover > 1.5·band` → 判定为真实抬脚，**不动**（不压非接触帧）；
   - 在接触区间内施加**同一个常数 drop**，区间边界做 3 帧斜坡，且斜坡完全在区间内部
     → **非接触帧一个都不改**（自检逐帧验证）。
4. **2-bone IK**：目标踝 = 当前踝 − (0, drop, 0)，在当前 hip-knee-ankle 平面内解；
   保留膝盖当前侧向；**脚的世界朝向保持不变**（只把父链的旋转补偿掉），
   因此 toe 的 XZ 严格不动 → 本阶段不可能让滑动变差。
   写出 大腿/膝盖/脚 三个局部四元数；**不写 IK 轨**，输出仍是 23 轨 + IK off。
5. **信任域**（每帧硬约束）：
   - 膝关节屈曲变化 ≤ **15°**（`--max-knee-deg`）；
   - 大腿摆角 ≤ 25°；可达性 ≤ 骨长（伸直到 (L1+L2)·(1−1e-4)）；
   - 单帧 drop ≤ 2.5% 身高；
   - 超限的帧只做“到上限为止”的修正并计数（`limits`），不改超；
   - `--trust-pct` 可把常数先缩到某个分位（本轮最终用 100，即不缩、逐帧钳制）。
6. **GT-free 自检**（`verify`，不通过直接非零退出）：骨长（1e-6）、脚世界朝向（<0.05°）、
   toe XZ（1e-6）、toe 垂直位移与计划 drop 一致（1e-6）、**非接触帧位移 0**（1e-6）。

## 5. 方法消融（为什么是 `mode=bias`）

前视，同一信任域（膝 15°）：

| 变体 | 常数/目标 | 召回 | 脚高% | jerk | 说明 |
|---|---|---:|---:|---:|---|
| 不修 | 0 | 0.461 | 2.05 | 2.897 | — |
| `mode=band`（逐帧压峰值） | 到带中心 | 0.7916 | 1.41 | 3.129 | 把误差的高频复制到膝盖 |
| `mode=bias`，`trust_pct=5`（常数缩到 p5 cap） | 0.191 | 0.701 | 1.24 | 3.054 | 为最直的 5% 帧牺牲整段 |
| **`mode=bias`，`trust_pct=100`（逐帧钳制）** | **0.370** | **0.8176** | **1.01** | **3.147** | 本轮采用 |
| `mode=bias`，膝 20°（超规格，仅参考） | 0.217 | 0.750 | 1.13 | 3.120 | p5 缩到 0.217 |

（`trust_pct=100` 行与“膝 15°”对应；膝 20° 那一行只用于说明上限。）

结论：把常数 drop 做满、让**每帧的膝角上限**兜底，比“预先缩常数”多拿 0.12 召回、
脚高再降 0.23%（%身高），只多 0.09 jerk。逐帧压峰值最差 —— 再一次说明
“把 2D/高度残差压小”不等于 3D 更好。

## 6. 上限与未解决

1. **残余是骨盆高度**：前视 hover 0.370，腿在 15° 内只能给到中位 0.232。
   要再降 0.14 就得让膝再伸（>15°，超出信任域）或**下移根骨 Y**。
   后者被开发指导 §2.5 明确禁止（会把另一只脚压向地面、等于假装着地），本轮不做。
   若将来允许“有界根骨 Y 仅用于贴合地面 + 穿地约束”，前视召回可望到 0.9+；
   这是一个明确的 M2.3 实验，不是本轮交付。
2. **3/4 的滑动 2.12 没修**：不是 IK 引入的（IK 前后完全相同），
   而是左脚的 XZ 漂移本来就大、cleanup 的 foot_lock 因接触比例 <0.8 没锁。
   IK 把左腿接触比例抬到 100%，现在**可以**重跑 `clean_vmd --lock-contact-fraction`
   的低阈值去锁 XZ；本轮没做，避免把 root XZ 与腿 IK 混在一次归因里。
3. **精度少 1 帧**：3/4 左脚的精度 1.0→0.9976（250 帧里多 1 帧 FP），
   是“最低点放回地面”把某一帧推到 GT 频带下沿之外，量级可忽略但如实记录。
4. **前视 jerk +0.25（相对清理后的输入）**：来自近直腿的 IK 放大
   （小腿关节 jerk ×1.56，集中在 214–233 帧，那里预测腿本身几乎伸直）。
   相对 M1.5 基线仍是 3.15 vs 4.76（−34%），门禁通过。
