> **执行结果见 `docs/M1.5_执行结果_D链修复与真实闭环.md`（已完成：D 链 bake、60° 回归、×2/×4/×8 对齐、三机位真实闭环）。**
> 本文记录 M1 验收时发现的一个**会直接影响视觉验收**的问题：Blender 里腿部 D 链没有跟随 FK 腿。

---

## 0. 一句话

M1 的数值/adapter 是好的；但 **Blender 渲染的腿不可信**：祀的腿部网格几乎全部权重在 `足D/ひざD/足首D`，而 VMD 只写 23 根 FK 骨，Blender 里 D 链没有约束/驱动，腿保持直。先修这个，再做真实闭环。

---

## 1. 验收发现（关键）

### 1.1 `cmp_121` 本身有时间错位

T5 源是 60fps/484 帧，VMD 是 30fps/242 帧。`cmp_121` 很可能拿 **源第 121 帧（2.02s）** 对比 **VMD 第 121 帧（4.03s）**，差 2 倍。

正确映射：

```
source_frame = round(vmd_frame * source_fps / (30 * slow_factor))
T5: 2×  (VMD 121 ↔ 源 242)
T2: 4×  (VMD 121 ↔ 源 484)
T1: 8×  (VMD 121 ↔ 源 968)
```

我先按对齐后的源 242 重新比：源是抬腿/手臂下垂，目标是直腿/手抬到脸前。**即使对齐，姿态也不一致**；但下面的 D 链问题比时间错位更根本。

### 1.2 直腿不是“M1 正常误差”，是 Blender D 链没跟随

实测：

- 祀腿部区域 2926 个顶点，主权重几乎全在 D 链：
  `左ひざD 705`、`左足首D 535`、`左足D 116`（右侧同理）；FK `左足/左ひざ/左足首` 在该区域权重为 **0**。
- VMD `outputs/t5_m1/t5_242.vmd` 第 26 帧：右膝角 **51.2°**（明显弯曲）。
- 同一帧渲染 `outputs/t5_m1/front/frames/frame_0027.png`：两条腿仍是**直的**（还离地）。
- `profiles/blender_wangpai.json`：`左ひざD/左足D/左足首D` 的 `constraints` 为空；D 骨有旧的 10 条 fcurves，但 VMD 只导入 23 根 FK 轨，D 骨不会跟着 T5 的 FK 腿走。
- PMX 求值器（`pose_track`）是按 `付与親` 算的，所以数值上膝角 51° 是对的；**数值对，Blender 视觉不对**。

结论：

- adapter/GVHMR **不是直腿的直接原因**；M1 的数值往返/指标仍有效。
- **M1 的 Blender 腿部视觉验收无效**；在此之前不能根据渲染说“腿没问题”，也不能用渲染去调 adapter/GVHMR。
- R2 GT 渲染腿不明显，是因为 R2 本身膝角多在 135–141°（接近直）；T5 帧 26 的 51° 才是决定性反例。

### 1.3 手臂/手高

手臂网格大概率权重在 FK 臂骨，所以手臂会动；但 `cmp_121` 的 2× 时间错位会让手高看起来不对。D 链修复 + 对齐后，再判断手高是前馈误差还是时间/映射误差。

## 2. P0：修复 Blender 的继承骨（D 链/twist/肩C）

### 2.1 目标

VMD 仍然只写 23 根 FK 骨（MMD 安全）；在 Blender 里，用 PMX 求值器把**所有继承骨**逐帧烘焙到 pose bones，再渲染。这样：

- MMD 播放：D 链靠 `付与親` 自动跟随，VMD 不写 D；
- Blender 播放：D 链由 bake 显式驱动，视觉正确；
- 两端的世界关节/网格一致。

### 2.2 实现

新增 `scripts/bake_inherit_blender.py`（或集成到 `render_synth.py`）：

1. 打开 .blend，导入 VMD（现有 `render_synth.py` 已做）；
2. 用 `src/vtv/mmd/evaluate` 按 MMD 语义求值 **全部 PMX 骨**（含 D 链、扭捩1、肩C/P、腰キャンセル等）；
3. 对每帧，把继承骨的 local rotation/translation 写到 Blender pose bones 并插 key；
4. 坐标换算：PMX/MMD `(x,y,z)` → Blender `(x,z,y)×12.5`（MMD Tools 导入约定；用现有 `render_synth.py` 的换算逻辑，不要另写一套）；
5. 清掉这些继承骨在旧 action 里的 fcurves，避免旧 R2 动作残留；
6. 渲染/保存。

备选：给 D 骨加 COPY_ROTATION/CHILD_OF 约束（D 链 100%、扭捩1 0.5、肩C -1.0）。约束更轻，但 MMD 付与親语义复杂；**bake 更可控**，建议先 bake。

### 2.3 验收

- [ ] T5 VMD 帧 26（渲染帧 27）侧视/正视：右膝应明显弯曲（VMD 51.2°），不是直腿；
- [ ] 造一个“左ひざ +60°”的测试 VMD：渲染腿必须弯；
- [ ] R2 GT 最弯帧（约 179）渲染腿应有弯曲；
- [ ] PMX 求值器世界关节 vs Blender bake 后 pose bone 世界位置 <1e-3 unit；
- [ ] 左/右腿都测；D 链 fcurves 不再残留旧动作；
- [ ] 把这个测试加入 `compatibility_report`/`m0_selftest`，防止回退。

### 2.4 重要边界

- 不要为了“让 Blender 腿动”而把 D 链写进 **MMD 用的 VMD**：MMD 会 D 链继承 + 显式轨双叠。
- 保持两套输出：`vmd_mmd`（23 轨）+ Blender 渲染时的 bake；或者单独的 `vmd_blender`（只给 Blender，不发布为 MMD 资产）。

## 3. P1：真实闭环基线（D 链修好后）

### 3.1 流程

```
outputs/synth/si_R2/{front,three_quarter,side}/gt_*.mp4
  → scripts/run_gvhmr.py（固定机位 -s；250 帧）
  → scripts/run_adapter.py --model si --slow-factor 1.0
  → outputs/.../*.vmd
  → scripts/closed_loop.py --pred ...（对 outputs/gt/si_R2_safe.vmd，23 身骨）
```

这是第一次测「渲染→识别→重定向」的真实精度。M1 只做了 VMD 级往返；这一步的误差主要来自 GVHMR/前馈。

### 3.2 指标

- 23 身骨 per-bone 相对角度/世界位置；
- 根轨迹/根高度；
- 接触 recall/precision/净滑动/穿地；
- jerk/spike；
- 三个机位分别看（正面/3-4/侧面）；
- 跨模型（R2→提弗洛斯/洛茜）另做一组，分开 adapter 与 feed-forward。

### 3.3 扰动

给合成 GT 加噪声/模糊/遮挡/裁剪/亮度变体，再跑同一闭环，区分“干净渲染上的误差”和“真实视频上的误差”。

## 4. P2：选择性清理（真实基线之后）

- T5 jerk 1e4；源自身手臂 10–14°/帧；不要全局滤波；
- Hampel/中值只修 flagged 帧；
- 接触区间净滑动/脚锁；
- 根漂移/穿地；
- 清理前后对比 jerk、高频能量、脚滑、per-bone；保留舞蹈发力；
- 门禁用向量/Pareto，不用 `summary_S`。

清理跑完、知道残差主要在哪，再做结构后馈/流式；不要现在先写网络。
