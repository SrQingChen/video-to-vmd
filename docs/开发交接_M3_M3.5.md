## 3. 执行顺序

### 第一步：M3 手部 + 表情（先做）

**M3.0（0.5–1 天）**：T5 抽 30–50 帧，测 MediaPipe Hands 与 WiLoR（或 HaMeR）的检测率、稳定性、耗时；写 `docs/M3.0_手部可行性.md`。

**M3.1 手部**：

- 首选 WiLoR；HaMeR 备选；没有 MANO 权重时先用 MediaPipe 打通 L0–L3 和 VMD 手指轨；
- 按 `profiles/*.json` 的 `finger_map` 写 30 根手指局部旋转；
- L0 3D、L1 2D+IK、L2 微屈、L3 中性；
- 左右手用身体手腕消歧；不写位移/helper；
- VMD：身体 23 + 手指 30 轨 + 4 IK off。

**M3.2 表情**：

- MediaPipe Face Landmarker/blendshape → 每模型 morph 别名（41/41/64，常用 21）；
- 眨眼/口型平滑；不可检测走程序化眨眼/中性 fallback；
- 不写不存在的 morph；每模型别名表从 profile 生成。

**M3.3 验收**：

- T5 三模型 2K；手/脸可见自然，不可见 fallback 平滑；
- 身体轨不变；D 链 0/0；828 骨 verify <2e-6；无 scale warning；
- 报告 L0/L1/L2/L3 比例、手检测率、morph 覆盖率、失败片段；
- 人工修正 ≤ 个别片段。

### 第二步：M3.5 数据引擎 + 自研后馈网络

**M3.5.1 数据引擎**：

- R1/R2/R3（可选 AMASS）→ 三模型固定机位渲染（手/脸加近景）→ 遮挡/丢帧/噪声
  → GVHMR→adapter→cleanup+ik/M3 → 与 GT 比对；
- 保存配对数据：GT、当前输出、2D 证据/置信度、接触、目标 profile、mask、split；
- 按动作/模型/机位整段划分；禁止 GT/像素进入推理输入。

**M3.5.2 网络**：

- 1–5M MLP/GRU；输入当前姿态/速度/2D 证据/置信度/接触/不确定性/目标 profile；
- 输出有界低维残差（根 XZ/脊柱/四肢 swing/roll/接触/手/脸）；
- 先离线窗口，再因果/流式；
- 教师：当前确定性结构反馈 + GT；不用像素/剪影；
- 留出集必须稳定优于 `cleanup+ik`，接触/穿透/时序不劣化，T5 视觉不退化；
- 不达标就不默认启用；不要用放宽门禁通过。

## 4. 合成闭环在哪个阶段用

| 阶段 | 用途 | 输入/输出 |
|---|---|---|
| M0/M1/M1.5 | 建立尺子、验证 adapter/D 链 | GT VMD→渲染→管线→VMD'→逐骨比较 |
| M2/M2.2/M2.5 | 清理/接触/流式回归 | 合成丢帧/遮挡 + GT；不比像素 |
| **M3** | 手/脸评测/调参 | GT VMD（含手指/morph）→ 渲染 → 管线 → 比手指角/morph |
| **M3.5** | **数据引擎 + 教师** | GT→渲染/增强→管线→与 GT 比→低维残差→训练网络 |
| M4 | 发布前回归/CI | 三模型/多动作固定机位；耗时只报告 |

**运行时没有 GT**：产品推理只用证据和当前输出；闭环只在开发/训练/评测用。
